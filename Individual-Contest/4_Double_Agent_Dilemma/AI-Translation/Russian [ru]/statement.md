# Дилемма двойного агента

- **Ограничение по времени:** 12 minutes.
- **Хранилище:** 5 GB
- **Среда:** один GPU (≈16 GB VRAM), без доступа к интернету
- **Размер решения:** `solution.ipynb` ≤ 1 MB
- **Бейзлайн:** 0 
- **Результат Научного комитета:** 96.99 

В национальном центре искусственного интеллекта в Астане две компьютерные модели — модель R (ResNet-18) и модель V (ViT-Tiny) — анализируют фотографии. В данный момент обе модели справляются идеально, демонстрируя точность 100% и совпадая в предсказаниях для каждого изображения. Чтобы проверить, насколько в действительности различаются их умные «мозги», главный научный сотрудник ставит перед вами задачу: внести в каждую фотографию крошечные, почти незаметные изменения пикселей так, чтобы модель R и модель V полностью разошлись в своих предсказаниях.

![изображение](../../dilemma.jpg)

## 1. Задача

Два предобученных классификатора изображений рассматривают одно и то же изображение. На изображениях, предоставленных в этой задаче, оба классификатора демонстрируют точность 100%.

- **Модель R**: `torchvision.models.resnet18` (CNN, ResNet18).
- **Модель V**: `vit_tiny_patch16_224` от `timm` (Transformer, ViT-Tiny).

Ваша задача — создать небольшое изменение («возмущение») для каждого изображения так, чтобы две модели разошлись в своих предсказаниях. Для каждого изображения вы должны создать **два разных** возмущения:

- **Тип A**: после его добавления модель R по-прежнему классифицирует изображение правильно, но модель V классифицирует его неправильно.
- **Тип B**: после его добавления модель V по-прежнему классифицирует изображение правильно, но модель R классифицирует его неправильно.

Каждое возмущение должно быть достаточно *малым*, чтобы его было трудно заметить. За меньшие возмущения начисляется больше баллов (см. раздел 5). Возмущение применяется непосредственно к исходному изображению на уровне пикселей.

## 2. Открытые данные

Вместе с задачей предоставляется набор изображений, разделённый на две выборки — `train` (100 изображений) и
`test_public` (100 изображений), — каждая из которых содержит изображения различного разрешения. Все изображения относятся к 1000 классам ImageNet-1K, и обе модели, R и V, достигают точности 100% на обеих выборках.

Предоставляются следующие файлы:

```text
train/images/*.png         # 100 images in PNG format
train/labels.json          # maps each image index to its correct class
test_public/images/*.png   # 100 images in PNG format
test_public/labels.json    # maps each image index to its correct class
```

Во время проверки ваша папка `dataset/test_public/` незаметно заменяется двумя скрытыми наборами изображений (`test_leaderboard_a` и `test_leaderboard_b`) для официального оценивания. Каждый из них содержит **100 изображений** в формате PNG и файл с метками. 

**Примечание: в этой задаче метки в тестовых датасетах доступны.**

## 3. Формат выходных данных

Для каждого изображения вы должны создать два файла:

```text
{index}_a.pt   # Type A perturbation
{index}_b.pt   # Type B perturbation
```

- `{index}` (`0`, `1`, `2`, ...), соответствует имени изображения в датасетах.
- Каждый файл представляет собой один тензор, сохранённый с помощью `torch.save`. Его форма должна быть`3 x H x W`, где `H` и `W` соответствуют **исходному** разрешению этого изображения (не `224 x 224`).
- Код должен создавать только один ZIP-файл — `submission.zip`. Поместите все файлы `.pt` на верхний уровень ZIP-архива, без охватывающей их папки или подкаталогов. 

```text
submission.zip
├── 0_a.pt
├── 0_b.pt
└── 1_a.pt
└── ...
```

Ноутбук предупредит вас, если с форматом выходных данных возникнут какие-либо проблемы.

## 4. Ограничения

- **Модели:** вы должны использовать `torchvision.models.resnet18(pretrained=True)` и `timm.create_model('vit_tiny_patch16_224', pretrained=True)`. Использовать другие предобученные модели нельзя.
- **Конвейер преобразований (принудительно применяется при оценивании):** `Resize(256) → CenterCrop(224) →
  Normalize(mean=[0.485,0.456,0.406], std=[0.229,0.224,0.225])`. See Section 3 of `baseline.ipynb` для подробностей. 
- **Разрешение возмущения:** должно соответствовать **исходному** разрешению необработанного изображения (не 224×224). Тензор
  добавляется к необработанному изображению *до* применения конвейера преобразований.
- **Формат выходных данных:** только файлы `.pt` — никаких PNG/JPG . Тензоры добавляются к необработанному изображению, а значения пикселей перед предобработкой ограничиваются диапазоном `[0, 1]`.
- **Именование файлов:** плоский список, строгий формат `{index}_a.pt` / `{index}_b.pt`. Внутри ZIP-архива не должно быть подкаталогов.
- **Библиотеки:** `torch`, `torchvision`, `timm`. 

## 5. Оценивание

Итоговый результат вычисляется следующим образом. Пусть `M` — количество изображений в выборке, $Score_A$ — количество успешных возмущений типа A, а $Score_B$ — количество успешных возмущений типа B:
$$
S_{final} = \frac{Score_A + Score_B}{2M} \times PF
$$

PF — это функция, предназначенная для штрафования возмущений с высокой нормой и обладающая очень высокой чувствительностью вблизи верхней границы результата. Она она ограничена диапазоном от 0.5 до 1. Полную реализацию можно увидеть в разделе  8 файла `solution.ipynb`.
