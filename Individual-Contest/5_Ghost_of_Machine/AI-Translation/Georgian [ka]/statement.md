# მანქანის აჩრდილი (Ghost of the Machine)

- **დროის ლიმიტი:** 10 წუთი
- **საბაზისო ქულა (Baseline score):** 28.6
- **სამეცნიერო კომიტეტის ქულა:** 93.41
- **გარემო:** ერთი GPU (≈16 GB VRAM), ინტერნეტის გარეშე
- **ამოხსნის ზომა:** `solution.ipynb` ≤ 20 MB
- **მეხსიერება:** 5 GB
- **წინასწარ დატრენინგებული მოდელები:** მხოლოდ **[bge-base-en-v1.5](https://yastatic.net/s3/contest/ioai/5/01_BAAI_bge-base-en-v1.5_MODEL_CARD.html)** — ტექსტის **ენკოდერი (encoder)** (ემბედინგის მოდელი).


## დავალება

ყაზახეთის ეროვნულ არქივში უცნაური ამბები ხდება. ბიბლიოთეკარები ამბობენ, რომ ზოგიერთი წიგნი ადრე სხვანაირად მთავრდებოდა, თუმცა ამის დამტკიცება არავის შეუძლია — თითოეული ეგზემპლარი იდენტურია და თითოეული ისტორია მაინც აზრს ინარჩუნებს. თქვენ, როგორც AI მკვლევარი, მოწვეული ხართ ამ ცვლილებების აღმოსაჩენად.
![აჩრდილი](../../ghost.jpg)

ტექსტის მონაკვეთი იწყება ადამიანის მიერ დაწერილი ტექსტით და, გარკვეულ მომენტში, უჩუმრად გადადის ენობრივი მოდელის მიერ გენერირებულ გაგრძელებაზე. მთლიანობაში წაკითხვისას ის ერთ შინაარსობრივად გამართულ ტექსტს ჰგავს — თუმცა სადღაც შუაში ავტორი ადამიანიდან მანქანაზე იცვლება. თქვენი დავალებაა **იპოვოთ ეს გადასვლა: სიმბოლოს ინდექსი (character index), სადაც ადამიანის ნაწილი მთავრდება და იწყება მანქანის ნაწილი**.

თითოეული ნიმუში (sample) არის ერთი სტრიქონი `text`. არსებობს ზუსტად ერთი საზღვარი. ყველაფერი მის წინ ადამიანისაა; ყველაფერი მის შემდეგ — მანქანის მიერ გენერირებული.

## მონაცემთა სიმრავლე (Dataset)

ჩვეულებრივი ინგლისურენოვანი ტექსტური მონაკვეთები, თითოეული ერთი საზღვრით.

- **ნაწილი A** (საზღვრამდე): ადამიანის მიერ დაწერილი ტექსტის ამონარიდი.
- **ნაწილი B** (საზღვრიდან მოყოლებული): ენობრივი მოდელის მიერ გენერირებული გაგრძელება, ნაწილი A-ზე დაყრდნობით.
- თითოეული მხარე შეიცავს სულ მცირე 180 სიტყვას; საერთო სიგრძეა ~500–800 სიტყვა.
- **`boundary_char_index`** არის სიმბოლოს გადანაცვლება (character offset), სადაც ნაწილი A მთავრდება:
  `text[:boundary_char_index]` არის ადამიანის ნაწილი და
  `text[boundary_char_index:].lstrip()` არის მანქანის ნაწილი.

#### რას იღებთ თქვენ

თქვენ იღებთ **ორ საქაღალდეს**:

| საქაღალდე | ნიმუშები | `answers.jsonl`? | გამოიყენეთ მისთვის, რომ |
|--------|---------|------------------|-----------|
| `dataset/train/` | 1,221 | ✅ მოყვება | დაატრენინგოთ / დაახვეწოთ (fine-tune) თქვენი მეთოდი |
| `dataset/test_public/`  | 380   | ✅ მოყვება (dev-ასლი) | გააშვათ თქვენი პაიპლაინი (pipeline) და შეაფასოთ საკუთარი შედეგი ლოკალურად |

**შეფასებისას** თქვენი `dataset/test_public/` საქაღალდე **ჩანაცვლდება დაფარული საგამოცდო სიმრავლით**. მას აქვს იგივე ფორმატი, მაგრამ **`answers.jsonl`-ის გარეშე**. თქვენი ნოუთბუქი (notebook) ხელახლა გაეშვება მასზე და მის მიერ გენერირებული `answers.jsonl` შეფასდება.

- საჯარო ლიდერბორდი იყენებს დაფარულ **test_leaderboard_a** სიმრავლეს (380 ნიმუში).

- საბოლოო რეიტინგი იყენებს დაფარულ **test_leaderboard_b** სიმრავლეს (380 ნიმუში).

სამივე საგამოცდო სიმრავლე არის იგივე ზომის და აღებულია იმავე განაწილებიდან, საიდანაც `train`, ასე რომ თქვენი ლოკალური `dataset/test_public/` ქულა არის თქვენი ლიდერბორდის ქულის გონივრული შეფასება.

#### ფორმატი დისკზე

```
dataset/train/data.jsonl      # one JSON object per line: {"id": "...", "text": "..."}
dataset/train/answers.jsonl   # {"id": "...", "boundary_char_index": 1842}
dataset/test_public/data.jsonl       # {"id": "...", "text": "..."}
dataset/test_public/answers.jsonl    # dev copy only — ABSENT in the hidden grading set
```

- id-ები `answers.jsonl`-ში ემთხვევა id-ებს `data.jsonl`-ში.
- `dataset/train/` (პასუხებით) ხელმისაწვდომია ყოველთვის, როდესაც ტრენინგს ან დახვეწას ახორციელებთ.

## გამოსატანი მონაცემები (გაზიარების ფორმატი)

თქვენ აგზავნით **ერთ ნოუთბუქს, რომელსაც აუცილებლად უნდა ერქვას `solution.ipynb`**. მოითხოვება ზუსტად ეს ფაილის სახელი. ნებისმიერი სხვა ფაილი უარყოფილი იქნება გაშვების გარეშე.

თქვენმა ნოუთბუქმა უნდა **წაიკითხოს `dataset/test_public/data.jsonl`** და ჩაწეროს ერთი ფაილი **`answers.jsonl`** რეპოზიტორიის ძირში — თითო JSON ობიექტი თითო სტრიქონზე, სადაც თითოეული ნიმუშის id ასახულია თქვენ მიერ იწინასწარმეტყველებ საზღვრის სიმბოლოს ინდექსზე:

```json
{"id": "example_000123", "boundary_char_index": 1790}
{"id": "example_000124", "boundary_char_index": 2450}
```

- `boundary_char_index` უნდა იყოს **მთელი რიცხვი `[0, len(text)]` დიაპაზონში**.
- `dataset/test_public/data.jsonl`-ში არსებული თითოეული id უნდა გამოჩნდეს ზუსტად ერთხელ. ნიმუში, რომელიც აკლია `answers.jsonl`-ს (ან აქვს არამთელი / დიაპაზონს გარეთ არსებული მნიშვნელობა), მიიღებს 0 ქულას ამ ნიმუშისთვის.

## შეფასება

თითოეული ნიმუშისთვის, დავუშვათ `p` არის თქვენ მიერ იწინასწარმეტყველები ინდექსი, ხოლო `t` — ჭეშმარიტი საზღვარი. თითოეული ნიმუშის ქულა ექსპონენციალურად მცირდება სიმბოლოებს შორის მანძილის ზრდასთან ერთად:

$$\text{score} = \exp\!\left(-\frac{|p - t|}{\tau}\right) \in (0, 1], 
~ \text{where} ~ \tau = 100.$$

ეს იწვევს ქულის შემდეგ ქცევას:
- **=1.0** — ზუსტი საზღვრის სიმბოლო;
- **≈0.78** — 25 სიმბოლოთი აცდენა; - **≈0.61** — 50 სიმბოლოთი აცდენა;
- **≈0.37** — 100 სიმბოლოთი აცდენა;
- **≈0.01** — 500 სიმბოლოთი აცდენა.

**საბოლოო ქულა არის** ყველა ნიმუშის ქულების **საშუალო (mean)** მოცემულ დაყოფაში (წარმოდგენილი 0–100 შკალაზე). მეტრიკა ასაჩუქრებს *მიახლოებასაც*, და არა მხოლოდ ზუსტ დამთხვევას.

## შეზღუდვები

- **გარემო:** ერთი GPU (≈16 GB VRAM), ინტერნეტის გარეშე შეფასებისას — დაშვებული მოდელი (ქვემოთ) უკვე უზრუნველყოფილია. **დროის ბიუჯეტი (Wall-clock budget): 10 წუთი** მთლიანი გაშვებისთვის — მან უნდა დაფაროს ნებისმიერი ტრენინგი / დახვეწა (fine-tuning), რომელსაც შეფასებისას გააკეთებთ, **პლუს** ინფერენსი (inference) საგამოცდო სიმრავლეზე.
- **დაშვებული წინასწარ დატრენინგებული მოდელი** — ეს სია ამომწურავია; სხვა წინასწარ დატრენინგებული წონების გამოყენება აკრძალულია. ის **წინასწარ არის უზრუნველყოფილი გარემოში** (ჩატვირთეთ ჩვეულებრივად, მაგ. `from_pretrained`; შეფასებისას ინტერნეტი არ არის):
  - **bge-base-en-v1.5** — 110M-პარამეტრიანი ტექსტის **ენკოდერი (encoder)** (ემბედინგის მოდელი). ის აგენერირებს წინადადების/მონაკვეთის ემბედინგებს; ის არ არის გენერაციული ენობრივი მოდელი. შეგიძლიათ გამოიყენოთ ის **უცვლელად (გაყინული ნიშნები / frozen features) ან დაახვეწოთ (fine-tune) `train` დაყოფაზე** (სრული fine-tuning ეტევა 16 GB / 10-წუთიან ბიუჯეტში).
- კლასიკური / სტატისტიკური ინსტრუმენტები შეუზღუდავია: შეგიძლიათ ააგოთ ნებისმიერი ნიშნებზე დაფუძნებული მოდელი (მაგ., scikit-learn კლასიფიკატორები ან რეგრესორები) თქვენ მიერ გამოთვლილი ემბედინგების ნიშნების ბაზაზე. *წინასწარ დატრენინგებული ღრმა სწავლების წონები (pretrained deep-learning weights)* შეზღუდულია მხოლოდ ზემოთ მოყვანილი სიით.

## საბაზისო მოდელი (Baseline)

მოწოდებული `solution.ipynb` არის ტრივიალური მაგალითი: ის ითვლის ერთადერთ „საშუალო საზღვრის წილს“ `dataset/train/`-იდან და იწინასწარმეტყველებს სიგრძის იმავე წილს თითოეული საგამოცდო მონაკვეთისთვის. ის იღებს **28.6** ქულას დაფარულ **test_leaderboard_a** დაყოფაზე და არსებობს მხოლოდ როგორც გაშვებადი შაბლონი read-`dataset/test_public/` → write-`answers.jsonl` ციკლისთვის.

**სამეცნიერო კომიტეტის ქულა 93.41**, რომელიც გაზომილია იმავე დაყოფასა და იმავე 10-წუთიან ბიუჯეტზე, მიიღება დაშვებული ენკოდერის `train`-ზე დახვეწით (fine-tuning) და გადასვლის ლოკალიზებით, როგორც ცვლილების წერტილის (changepoint) წინადადებებს შორის. ეს არ არის ზედა ზღვარი — ამ მეტრიკის მაქსიმუმი არის 100.
