# ภูตแห่งจักรกล

- **เวลาจำกัด:** 10 นาที
- **คะแนน baseline:** 28.6
- **คะแนนคณะกรรมการวิทยาศาสตร์:** 93.41
- **สภาพแวดล้อม:** GPU หนึ่งตัว (VRAM ≈16 GB), ไม่มีอินเทอร์เน็ต
- **ขนาดโซลูชัน:** `solution.ipynb` ≤ 20 MB
- **พื้นที่จัดเก็บ:** 5 GB
- **โมเดลที่ฝึกไว้ล่วงหน้า:** เฉพาะ **[bge-base-en-v1.5](https://yastatic.net/s3/contest/ioai/5/01_BAAI_bge-base-en-v1.5_MODEL_CARD.html)** — **encoder** ข้อความ (โมเดล embedding)


## โจทย์

กำลังเกิดเหตุการณ์ประหลาดขึ้นที่หอจดหมายเหตุแห่งชาติของคาซัคสถาน บรรณารักษ์กล่าวว่าหนังสือบางเล่มเคยมีตอนจบที่แตกต่างออกไป แต่ไม่มีใครพิสูจน์ได้ — สำเนาทุกฉบับเหมือนกัน และทุกเรื่องราวยังคงสมเหตุสมผล คุณได้รับเชิญในฐานะนักวิจัย AI เพื่อค้นหาการเปลี่ยนแปลงเหล่านั้น
![ภูต](../../ghost.jpg)

ข้อความตอนหนึ่งเริ่มต้นด้วยข้อความที่มนุษย์เขียน และ ณ จุดหนึ่งจะเปลี่ยนอย่างแนบเนียน
ไปเป็นข้อความต่อเนื่องที่สร้างโดยโมเดลภาษา เมื่ออ่านโดยรวมแล้ว ข้อความดูเหมือนเป็น
งานเขียนชิ้นเดียวที่สอดคล้องกัน — แต่ที่ใดที่หนึ่งตรงกลาง ผู้เขียนเปลี่ยนจากมนุษย์
เป็นเครื่องจักร งานของคุณคือ **หาจุดเปลี่ยนนั้น: ดัชนีอักขระที่ส่วนของมนุษย์
สิ้นสุดลงและส่วนของเครื่องจักรเริ่มต้นขึ้น**

แต่ละตัวอย่างเป็นสตริง `text` เพียงหนึ่งสตริง มีขอบเขตเพียงหนึ่งจุดเท่านั้น ทุกสิ่ง
ก่อนจุดนั้นเป็นของมนุษย์ ทุกสิ่งตั้งแต่จุดนั้นเป็นต้นไปสร้างโดยเครื่องจักร

## ชุดข้อมูล

ข้อความภาษาอังกฤษแบบข้อความล้วน โดยแต่ละข้อความมีขอบเขตหนึ่งจุด

- **ส่วน A** (ก่อนขอบเขต): ข้อความตัดตอนจากงานเขียนของมนุษย์
- **ส่วน B** (ตั้งแต่ขอบเขตเป็นต้นไป): ข้อความต่อเนื่องที่สร้างโดยโมเดลภาษา
  โดยมีส่วน A เป็นเงื่อนไข
- แต่ละส่วนมีอย่างน้อย 180 คำ ความยาวรวมอยู่ที่ ~500–800 คำ
- **`boundary_char_index`** คือออฟเซตอักขระที่ส่วน A สิ้นสุดลง:
  `text[:boundary_char_index]` คือส่วนของมนุษย์ และ
  `text[boundary_char_index:].lstrip()` คือส่วนของเครื่องจักร

#### สิ่งที่คุณได้รับ

คุณจะได้รับ **สองโฟลเดอร์**:

| โฟลเดอร์ | ตัวอย่าง | `answers.jsonl`? | ใช้เพื่อ |
|--------|---------|------------------|-----------|
| `dataset/train/` | 1,221 | ✅ มีให้ | ฝึก / fine-tune วิธีการของคุณ |
| `dataset/test_public/`  | 380   | ✅ มีให้ (สำเนา dev) | รัน pipeline ของคุณและคำนวณคะแนนด้วยตนเองภายในเครื่อง |

ณ **เวลาตรวจให้คะแนน** โฟลเดอร์ `dataset/test_public/` ของคุณจะถูก **แทนที่ด้วย
ชุดประเมินที่ซ่อนไว้** ซึ่งมีรูปแบบเดียวกันแต่ **ไม่มี `answers.jsonl`** notebook ของคุณ
จะถูกรันซ้ำกับชุดดังกล่าว และ `answers.jsonl` ที่ notebook สร้างขึ้นจะถูกนำไปคำนวณคะแนน

- leaderboard สาธารณะใช้ชุด **test_leaderboard_a** ที่ซ่อนไว้ (380 ตัวอย่าง)

- การจัดอันดับรอบสุดท้ายใช้ชุด **test_leaderboard_b** ที่ซ่อนไว้ (380 ตัวอย่าง)

ชุดประเมินทั้งสามชุด
มีขนาดเท่ากันและสุ่มมาจากการแจกแจงเดียวกันกับ `train` ดังนั้นคะแนน
`dataset/test_public/` ภายในเครื่องของคุณจึงเป็นค่าประมาณที่สมเหตุสมผลสำหรับคะแนนบน leaderboard ของคุณ

#### รูปแบบที่จัดเก็บบนดิสก์

```
dataset/train/data.jsonl      # one JSON object per line: {"id": "...", "text": "..."}
dataset/train/answers.jsonl   # {"id": "...", "boundary_char_index": 1842}
dataset/test_public/data.jsonl       # {"id": "...", "text": "..."}
dataset/test_public/answers.jsonl    # dev copy only — ABSENT in the hidden grading set
```

- ID ใน `answers.jsonl` ตรงกับ ID ใน `data.jsonl`
- `dataset/train/` (พร้อมคำตอบ) สามารถใช้งานได้ทุกครั้งที่คุณฝึกหรือ fine-tune

## เอาต์พุต (รูปแบบการส่งคำตอบ)

คุณต้องส่ง **notebook เพียงไฟล์เดียว ซึ่งต้องมีชื่อว่า `solution.ipynb`** จำเป็นต้องใช้ชื่อไฟล์นี้ทุกประการ ไฟล์ที่ใช้ชื่ออื่นจะถูกปฏิเสธโดยไม่ถูกรัน

notebook ของคุณต้อง **อ่าน `dataset/test_public/data.jsonl`** และเขียนไฟล์เดียว
คือ **`answers.jsonl`** ที่รากของ repository — หนึ่งออบเจกต์ JSON ต่อบรรทัด โดยแมป
ID ของแต่ละตัวอย่างกับดัชนีอักขระขอบเขตที่คุณทำนาย:

```json
{"id": "example_000123", "boundary_char_index": 1790}
{"id": "example_000124", "boundary_char_index": 2450}
```

- `boundary_char_index` ต้องเป็น **จำนวนเต็มใน `[0, len(text)]`**
- ทุก ID ใน `dataset/test_public/data.jsonl` ควรปรากฏเพียงหนึ่งครั้งพอดี ตัวอย่างที่หายไป
  จาก `answers.jsonl` (หรือมีค่าที่ไม่ใช่จำนวนเต็ม / อยู่นอกช่วง) จะได้คะแนน 0
  สำหรับตัวอย่างนั้น

## การให้คะแนน

สำหรับแต่ละตัวอย่าง ให้ `p` เป็นดัชนีที่คุณทำนาย และ `t` เป็นขอบเขตจริง คะแนนต่อหนึ่งตัวอย่างจะลดลงแบบเอ็กซ์โพเนนเชียลตามระยะห่างเป็นจำนวนอักขระ:

$$\text{score} = \exp\!\left(-\frac{|p - t|}{\tau}\right) \in (0, 1], 
~ \text{where} ~ \tau = 100.$$

ซึ่งทำให้คะแนนมีพฤติกรรมดังต่อไปนี้:
- **=1.0** — ตรงกับอักขระขอบเขตพอดี
- **≈0.78** — คลาดเคลื่อน 25 อักขระ; - **≈0.61** — คลาดเคลื่อน 50 อักขระ
- **≈0.37** — คลาดเคลื่อน 100 อักขระ
- **≈0.01** — คลาดเคลื่อน 500 อักขระ

**คะแนนสุดท้ายคือค่าเฉลี่ย** ของคะแนนต่อหนึ่งตัวอย่างจากตัวอย่างทั้งหมดใน split
(รายงานในสเกล 0–100) metric นี้ให้คะแนนเมื่อทำนายได้ *ใกล้เคียง* ไม่ใช่เฉพาะเมื่อตรงพอดีเท่านั้น

## ข้อจำกัด

- **สภาพแวดล้อม:** GPU หนึ่งตัว (VRAM ≈16 GB), ไม่มีอินเทอร์เน็ต ณ เวลาตรวจให้คะแนน — โมเดลที่อนุญาต
  (ด้านล่าง) ถูกจัดเตรียมไว้แล้ว **งบเวลาตามเวลาจริง: 10 นาที** สำหรับการรัน
  ทั้งหมด — ซึ่งต้องครอบคลุมทั้งการฝึก / fine-tuning ใด ๆ ที่คุณทำ ณ เวลาตรวจให้คะแนน
  **รวมถึง** inference บนชุดประเมิน
- **โมเดลที่ฝึกไว้ล่วงหน้าที่อนุญาต** — รายการนี้ครอบคลุมทั้งหมด ไม่อนุญาตให้ใช้ weights ที่ฝึกไว้ล่วงหน้าอื่นใด
  โมเดลนี้ **ถูกจัดเตรียมไว้ล่วงหน้าในสภาพแวดล้อม** (โหลดตามปกติ เช่น
  `from_pretrained`; ไม่มีอินเทอร์เน็ต ณ เวลาตรวจให้คะแนน):
  - **bge-base-en-v1.5** — **encoder** ข้อความขนาด 110M พารามิเตอร์ (โมเดล embedding) โมเดลนี้
    สร้าง embedding ของประโยค/ข้อความ ไม่ใช่โมเดลภาษาเชิงกำเนิด คุณ
    อาจใช้โมเดลนี้ **ตามที่เป็นอยู่ (frozen features) หรือ fine-tune บน split `train`**
    (การทำ full fine-tuning อยู่ภายในงบ 16 GB / 10 นาที)
- เครื่องมือแบบดั้งเดิม / เชิงสถิติไม่มีข้อจำกัด: คุณอาจสร้างโมเดลที่ใช้ฟีเจอร์แบบใดก็ได้
  (เช่น classifier หรือ regressor ของ scikit-learn) บนฟีเจอร์ embedding ที่คุณ
  คำนวณขึ้นเอง *weights ของ deep learning ที่ฝึกไว้ล่วงหน้า* ถูกจำกัดเฉพาะรายการข้างต้นเท่านั้น

## Baseline

`solution.ipynb` ที่ให้มาเป็นเพียงตัวอ้างอิงพื้นฐาน: มันประมาณ
"สัดส่วนขอบเขตเฉลี่ย" ค่าเดียวจาก `dataset/train/` และทำนายตำแหน่งที่เป็นสัดส่วนเดียวกันของ
ความยาวสำหรับข้อความทดสอบทุกข้อความ มันได้คะแนน **28.6** บน split
**test_leaderboard_a** ที่ซ่อนไว้ และมีไว้เพียงเป็นเทมเพลตที่รันได้สำหรับลูป
อ่าน-`dataset/test_public/` → เขียน-`answers.jsonl`

**คะแนนของคณะกรรมการวิทยาศาสตร์ที่ 93.41** ซึ่งวัดบน split เดียวกันและภายใต้
งบเวลา 10 นาทีเดียวกัน มาจากการ fine-tune encoder ที่อนุญาตบน `train` และระบุ
ตำแหน่งจุดเปลี่ยน (changepoint) บนลำดับประโยค คะแนนนี้ไม่ใช่ขอบเขตบน — ค่าสูงสุด
ของ metric นี้คือ 100.
