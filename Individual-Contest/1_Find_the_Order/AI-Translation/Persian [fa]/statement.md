# یافتن ترتیب

- **محدودیت زمان:** 10 دقیقه
- **محیط:** یک GPU (≈16 GB VRAM)، بدون اینترنت
- **اندازهٔ راه‌حل:** `solution.ipynb` ≤ 1 MB
- **فضای ذخیره‌سازی:** 5 GB 

## مسئله

دیالوگ‌های گفتاری انگلیسی میان دو شرکت‌کننده، *Speaker A* و *Speaker B*، به شما داده می‌شود. هر دیالوگ به نوبت‌های گویندگان بخش‌بندی شده است، به‌طوری‌که هر نوبت فقط شامل گفتار یک گوینده است. هر نوبت به‌صورت یک فایل صوتی جداگانهٔ `.wav` ذخیره شده است؛ بنابراین، یک دیالوگ کامل با مجموعه‌ای از فایل‌های `.wav`، یک فایل برای هر نوبت، نمایش داده می‌شود. 

متأسفانه، نوبت‌ها به‌صورت تصادفی درهم‌ریخته‌اند، بنابراین مکالمه دیگر معنادار نیست. در نام فایل `chunk_{k}.wav`، `k` به kاُمین قطعه در مجموعهٔ درهم‌ریخته اشاره دارد، نه kاُمین نوبت در دیالوگ اصلی.

**‼️ وظیفهٔ شما بازسازی ترتیب زمانی اصلی مکالمه است.**

## مجموعه‌داده

هر دیالوگ شامل فایل‌های صوتی `n` با نام‌های `chunk_0.wav`، `chunk_1.wav`، …، `chunk_{n-1}.wav` است. قطعه‌ها نوبت‌های مجزا هستند. نام فایل‌ها فقط با ترتیب درهم‌ریخته مطابقت دارند. آن‌ها نشان نمی‌دهند که یک قطعه در کجای مکالمهٔ اصلی قرار دارد. هر دیالوگ دارای 7–20 قطعه، تک‌کاناله، با نرخ 44.1 kHz است (می‌توانید
بازنمونه‌برداری کنید).

**`prefix.json` شامل اندیس‌های نام فایلِ دو قطعهٔ نخست در هر دیالوگ است.** این مورد آغاز واقعی دیالوگ را مشخص می‌کند و ابهام میان خواندن مکالمه از ابتدا به انتها یا از انتها به ابتدا را از بین می‌برد.

برای مثال: `11: [7, 12]` به این معناست که نوبت‌های اول و دوم دیالوگ 11 به‌ترتیب `chunk_7.wav` و `chunk_12.wav` هستند.

### آنچه دریافت می‌کنید

شما **دو پوشه با قالب یکسان** دریافت می‌کنید:

| پوشه | دیالوگ‌ها | `answers.json`؟ | کاربرد |
|--------|-----------|-----------------|-----------|
| `dataset/train/` | 1,288 | ✅ موجود است | آموزش / تنظیم دقیق مدل خود |
| `dataset/test_public/`  | 100   | ✅ موجود است | اجرای خط لولهٔ خود و امتیازدهی محلی |

در زمان ارزیابی، پوشهٔ `dataset/test_public/` شما به‌صورت شفاف با
یک `hidden evaluation set` (`test_leaderboard_a` برای جدول امتیازات عمومی و `test_leaderboard_b` برای جدول امتیازات نهایی) جایگزین می‌شود — این‌ها اندازه و قالبی یکسان با `dataset/test_public/` دارند، اما فاقد `answers.json` هستند.

دفترچهٔ شما دوباره روی آن داده‌ها اجرا می‌شود و فایل `answers.json` که تولید می‌کند برای امتیازدهی استفاده می‌شود. دیالوگ‌های آزمونِ کنارگذاشته‌شده از همان توزیع `train` می‌آیند، بنابراین امتیاز محلی `test_public` شما پیش‌نمایشی قابل‌اعتماد است.

### ساختار پوشه‌ها

```bash
dataset/train/
    prefix.json  # {dialogue_id: [first_idx, second_idx]} filename index 
    answers.json  # {dialogue_id: P}  ground-truth order (rank convention)
    <dialogue_id>/
        chunk_0.wav
        ...
        chunk_{n-1}.wav

dataset/test_public/
    prefix.json
    answers.json     # present only in the development copy
    <dialogue_id>/
        chunk_0.wav
        ...
        chunk_{n-1}.wav
```

## خروجی

برای هر دیالوگ، ترتیب زمانی اصلی قطعه‌های صوتی آن را تعیین کنید. پیش‌بینی شما باید یک جایگشت `P` از `{0, 1, …, n−1}` باشد، که در آن `P[i]` موقعیت زمانی پیش‌بینی‌شدهٔ `chunk_i.wav` است (0 = نخستین).

فایل خروجی `answers.json` شما باید هر شناسهٔ دیالوگ را به جایگشت پیش‌بینی‌شدهٔ آن نگاشت کند:

```json
{
  "17": [2, 0, 1],
  "42": [0, 1],
  "108": [3, 1, 0, 4, 2, 5]
}
```

### مثال

یک دیالوگ دارای 3 قطعهٔ درهم‌ریختهٔ `chunk_0, chunk_1, chunk_2` است:

| قطعهٔ درهم‌ریخته | محتوای گفتاری | موقعیت واقعی (رتبه) |
|----------------|----------------|----------------------|
| `chunk_0.wav` | *«اشکالی ندارد — بعداً یادداشت‌ها را برایت می‌فرستم.»* | 2 (آخرین) |
| `chunk_1.wav` | *«سلام، به جلسهٔ ساعت سه می‌آیی؟»* | 0 (نخستین) |
| `chunk_2.wav` | *«نمی‌توانم — آن موقع وقت دندان‌پزشکی دارم.»* | 1 |

ترتیب واقعی **chunk_1 → chunk_2 → chunk_0** است، بنابراین `P = [2, 0, 1]`، و `prefix.json` مقدار `[1, 2]` را نگه می‌دارد.

⚠️ **P باید یک جایگشت واقعی باشد:** با طول n، دارای اندیس‌گذاری از 0، و شامل هر مقدار دقیقاً یک‌بار. مقادیر تکراری، مقادیر مفقود یا ورودی‌های خارج از محدوده (برای مثال، دارای اندیس‌گذاری از 1) برای آن دیالوگ امتیاز 0 می‌گیرند؛ دیالوگی که در فایل موجود نباشد نیز همین‌طور است. فایل بدقالب یا غیر JSON رد می‌شود.

## امتیازدهی

معیار امتیازدهی این وظیفه **دقت ترتیب‌دهی دوبه‌دو** است. این معیار هر جفت از قطعه‌ها را بررسی می‌کند و می‌پرسد: _کدام‌یک از این دو باید زودتر بیاید؟_ یک جفت زمانی صحیح است که پیش‌بینی شما همان پاسخ حقیقت مبنا را ارائه دهد. برای دیالوگی با `n` قطعه، $$M = n(n-1)/2$$ جفت وجود دارد؛ فرض کنید `I` تعداد وارونگی‌ها — جفت‌هایی که ترتیبی متفاوت از حقیقت مبنا دارند — باشد:

$$\text{score} = 1 - \frac{I}{M} \in [0, 1]$$

ℹ️ **امتیاز نهایی، میانگین امتیازهای هر دیالوگ در میان همهٔ
دیالوگ‌های بخش است.**

## مدل‌های مجاز

برای حل این وظیفه، هم در زمان آموزش و هم ارزیابی، فقط می‌توانید از مدل‌های ازپیش‌آموزش‌دیدهٔ زیر استفاده کنید. همهٔ این مدل‌ها از قبل دانلود شده‌اند و در محیط در دسترس هستند. می‌توانید نمونه‌های نحوهٔ استفاده از آن‌ها را در دفترچهٔ مبنا `solution.ipynb` مشاهده کنید. توجه داشته باشید که نمی‌توانید از هیچ مدل دیگری استفاده کنید و برنامهٔ شما به اینترنت دسترسی ندارد.

- **بازنمایی‌های گفتار:** **wav2vec 2.0**. از **Whisper encoder** نیز می‌توان به‌عنوان استخراج‌کنندهٔ ویژگی استفاده کرد.
[کارت مدل wav2vec](https://yastatic.net/s3/contest/ioai/1/01_facebook_wav2vec2-base-960h_MODEL_CARD.html)

- **تشخیص خودکار گفتار (ASR):** **OpenAI Whisper** (با هر اندازه‌ای).
[کارت مدل Whisper](https://yastatic.net/s3/contest/ioai/1/03_openai_whisper-small_MODEL_CARD.html)
- **مدل زبانی:** **Qwen2.5-0.5B**، که می‌توان از آن به‌صورت zero-shot یا پس از تنظیم دقیق روی بخش `train` ارائه‌شده استفاده کرد.
[کارت مدل Qwen](https://yastatic.net/s3/contest/ioai/1/02_Qwen_Qwen2.5-0.5B_MODEL_CARD.html)
توجه داشته باشید که محدودیت 10 دقیقه باید هرگونه آموزش یا تنظیم دقیقی را که در زمان ارزیابی انجام می‌دهید، به‌علاوهٔ استنتاج روی مجموعهٔ ارزیابی، پوشش دهد.
