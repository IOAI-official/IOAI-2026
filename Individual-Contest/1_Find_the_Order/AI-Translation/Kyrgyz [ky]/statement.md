# Иретти табуу

- **Убакыт чеги:** 10 мүнөт
- **Чөйрө:** бир GPU (≈16 GB VRAM), интернет жок
- **Чечимдин өлчөмү:** `solution.ipynb` ≤ 1 МБ
- **Сактагыч:** 5 ГБ 

## Маселе

Сизге эки катышуучунун (*Speaker A* жана *Speaker B*) ортосундагы англис тилиндеги сүйлөшүү диалогдору берилген. Ар бир диалог сүйлөөчү кезегине (speaker turn) бөлүнүп, ар бир кезек бир гана сүйлөөчүнүн кебин камтыйт. Ар бир кезек өзүнчө `.wav` аудио файлы катары сакталган, ошондуктан толук диалог ар бир кезек үчүн бирден аталган `.wav` файлдарынын топтому менен берилет. 

Тилекке каршы, сүйлөө кезектери туш келди аралаштырылып (shuffled) калгандыктан, сүйлөшүүнүн мааниси жоголгон. `chunk_{k}.wav` файл аталышындагы `k` түпнуска диалогдогу k-чи кезекти эмес, аралаштырылган топтомдогу k-чи бөлүктү (chunk) билдирет.

**‼️ Сиздин тапшырмаңыз — сүйлөшүүнүн түпнуска хронологиялык иретин калыбына келтирүү.**

## Берилген маалыматтар (Dataset)

Ар бир диалог `chunk_0.wav`, `chunk_1.wav`, …, `chunk_{n-1}.wav` деп аталган `n` аудио файлдарын камтыйт. Бөлүктөр (chunks) жеке сүйлөө кезектери болуп саналат. Файлдардын аталыштары аралаштырылган иретке гана ылайык келет. Алар бөлүктүн түпнуска сүйлөшүүдө кайсы жерде жайгашканын көрсөтпөйт. Ар бир диалогдо 7–20 бөлүк бар, моно, 44.1 кГц (кайра дискретизацияласаңыз болот).

**`prefix.json` ар бир диалогдогу алгачкы эки бөлүктүн файл аталышынын индекстерин камтыйт.** Бул диалогдун чыныгы башталышын аныктайт жана сүйлөшүүнү алдыга же артка окуудагы бүдөмүктүктү жок кылат.

Мисалы: `11: [7, 12]` деген 11-диалогдун биринчи жана экинчи кезектери тиешелүүлүгүнө жараша `chunk_7.wav` жана `chunk_12.wav` экенин билдирет.

### Сизге берилген нерселер

Сиз **бирдей форматтагы эки папканы** аласыз:

| Папка | Диалогдор | `answers.json`? | Колдонуу максаты |
|--------|-----------|-----------------|-----------|
| `dataset/train/` | 1,288 | ✅ камтылган | моделиңизди үйрөтүү / тактоо (train / fine-tune) |
| `dataset/test_public/`  | 100   | ✅ камтылган | пайплайнды иштетүү жана локалдуу түрдө өзүңүздү баалоо |

Баалоо учурунда сиздин `dataset/test_public/` папкаңыз тунук түрдө `hidden evaluation set` (ачык лидерборд үчүн `test_leaderboard_a` жана акыркы лидерборд үчүн `test_leaderboard_b`) папкасы менен алмаштырылат — булар `dataset/test_public/` менен бирдей өлчөмдө жана форматта болот, бирок `answers.json` жок.

Сиздин блокнотуңуз (notebook) ал маалыматтарда кайрадан аткарылат жана ал чыгарган `answers.json` файлы баалоо үчүн колдонулат. Сакталган тесттик диалогдор `train` сыяктуу эле бөлүштүрүүдөн келип чыгат, ошондуктан сиздин локалдуу `test_public` упайыңыз ишенимдүү алдын ала көрүнүш болуп саналат.

### Каталогдун түзүлүшү

```bash
dataset/train/
    prefix.json  # {dialogue_id: [first_idx, second_idx]} filename index 
    answers.json  # {dialogue_id: P}  ground-truth order (rank convention)
    <dialogue_id>/
        chunk_0.wav
        ...
        chunk_{n-1}.wav

dataset/test_public/
    prefix.json
    answers.json     # present only in the development copy
    <dialogue_id>/
        chunk_0.wav
        ...
        chunk_{n-1}.wav
```

## Чыгуучу маалымат

Ар бир диалог үчүн анын аудио бөлүктөрүнүн түпнуска хронологиялык иретин аныктаңыз. Сиздин болжолуңуз `{0, 1, …, n−1}` элементтеринин `P` орун алмаштыруусу (permutation) болушу керек, мында `P[i]` — бул `chunk_i.wav` үчүн болжолдонгон хронологиялык орун (0 = биринчи).

Сиздин чыгуучу `answers.json` файлыңыз ар бир диалогдун IDсин анын болжолдонгон орун алмаштыруусуна чагылдырышы (map) керек:

```json
{
  "17": [2, 0, 1],
  "42": [0, 1],
  "108": [3, 1, 0, 4, 2, 5]
}
```

### Мисал

Диалогдо аралаштырылган 3 бөлүк бар `chunk_0, chunk_1, chunk_2`:

| аралаштырылган бөлүк | айтылган мазмуну | чыныгы орду (ранг) |
|----------------|----------------|----------------------|
| `chunk_0.wav` | *"No worries — I'll send you the notes afterwards."* | 2 (акыркы) |
| `chunk_1.wav` | *"Hey, are you coming to the three o'clock meeting?"* | 0 (биринчи) |
| `chunk_2.wav` | *"I can't — I've got a dentist appointment then."* | 1 |

Чыныгы ирет: **chunk_1 → chunk_2 → chunk_0**, ошондуктан `P = [2, 0, 1]`, ал эми `prefix.json` мааниси `[1, 2]` болот.

⚠️ **P чыныгы орун алмаштыруу болушу керек:** узундугу n, 0дөн башталган индекстөө, ар бир маани так бир жолу кездешет. Кайталанмалар, жетишпеген маанилер же диапазондон тышкары жазуулар (мисалы, 1ден башталган индекстөө), ошондой эле файлда жок болгон диалог үчүн 0 упай берилет. Ката түзүлгөн же JSON форматында болбогон файл четке кагылат.

## Баалоо

Бул тапшырманы баалоо **жуптук иреттешүү тактыгы** (pairwise ordering accuracy) боюнча жүргүзүлөт. Ал бөлүктөрдүн ар бир жубун текшерип: _экөөнүн кайсынысы биринчи келиши керек?_ деп сурайт. Эгер сиздин болжолуңуз чыныгы мааниге (ground truth) дал келген жоопту берсе, жуп туура деп эсептелет. `n` бөлүгү бар диалог үчүн $$M = n(n-1)/2$$ жуп бар; `I` саны инверсиялардын — чыныгы мааниден башкача иреттелген жуптардын саны болсун:

$$\text{score} = 1 - \frac{I}{M} \in [0, 1]$$

ℹ️ **Акыркы упай — сплиттеги бардык диалогдор боюнча ар бир диалог үчүн алынган упайлардын орточо мааниси.**

## Уруксат берилген моделдер

Бул тапшырманы чечүү үчүн, үйрөтүү учурунда да, баалоо учурунда да, төмөнкү алдын ала үйрөтүлгөн (pre-trained) моделдерди гана колдоно аласыз. Бул моделдердин баары чөйрөгө алдын ала жүктөлгөн жана жеткиликтүү. Аларды кантип колдонуунун мисалдарын `solution.ipynb` баштапкы блокнотунан көрө аласыз. Башка эч бир моделди колдонууга болбойт жана программаңыздын интернетке чыгуу мүмкүнчүлүгү жок экенин эске алыңыз.

- **Кепти сунуштоо (Speech representations):** **wav2vec 2.0**. **Whisper энкодери** да белгилерди бөлүп алуучу (feature extractor) катары колдонулушу мүмкүн.
[wav2vec модель карточкасы](https://yastatic.net/s3/contest/ioai/1/01_facebook_wav2vec2-base-960h_MODEL_CARD.html)

- **Кепти автоматтык таануу (ASR):** **OpenAI Whisper** (каалаган өлчөмдөгү).
[Whisper модель карточкасы](https://yastatic.net/s3/contest/ioai/1/03_openai_whisper-small_MODEL_CARD.html)
- **Тил модели:** **Qwen2.5-0.5B**, аны zero-shot режиминде же берилген `train` сплитиде такталган (fine-tuned) түрүндө колдонсо болот.
[Qwen модель карточкасы](https://yastatic.net/s3/contest/ioai/1/02_Qwen_Qwen2.5-0.5B_MODEL_CARD.html)
10 мүнөттүк чектөө баалоо учурунда аткарылган бардык үйрөтүү же тактоо иштерин, ошондой эле баалоо топтомундагы инференсти (inference) камтышы керектигин эске алыңыз.

## Тапшыруу тартиби

- `solution.ipynb` файлы ачыңыз жана бардык уячаларды (cells) иштетиңиз. Ал жумушчу директорияда `dataset/test_public/` ичиндеги ар бир диалог (100 диалог) үчүн орун алмаштыруусу бар `answers.json` файлын жазганын ырастаңыз. Баалоо учурунда блокнот жашыруун тесттик топтомдо кайра иштетилип, ал жерде чыгарган `answers.json` файлы бааланат.
- Кааласаңыз чечимди жакшыртыңыз — же жакшыртпаңыз; баштапкы вариант (baseline) гана пайплайнды текшерет.
- JupyterLab'дын сол каптал тилкесиндеги Git өтмөгүн ачыңыз.
- `solution.ipynb` файлын **Stage** кылыңыз (жанындагы + сүрөтчөсү).
- Коммит билдирүүсүн киргизип, **Commit** баскычын чыкылдатыңыз.
- Пуш кылуу үчүн булут жана өйдө жебе сүрөтчөсүн чыкылдатыңыз.
- Бул Мелдеш барагына кайтып келип, **Submit** баскычын чыкылдатыңыз.

Дал эле бир файлды тапшырыңыз, аталышы: `solution.ipynb`.
