# Восстановите порядок

- **Ограничение времени:** 10 минут
- **Среда:** один GPU (≈16 GB VRAM), без доступа к интернету
- **Размер решения:** `solution.ipynb` ≤ 1 MB
- **Хранилище:** 5 GB 

## Задача

Вам даны англоязычные устные диалоги между двумя участниками, *Говорящим A* и *Говорящим B*. Каждый диалог разделён на реплики, причём каждая реплика содержит речь только одного говорящего. Каждая реплика хранится в отдельном аудиофайле `.wav`, поэтому полный диалог представлен набором файлов `.wav` — по одному для каждой реплики. 

К сожалению, реплики были случайным образом перемешаны, поэтому разговор больше не имеет смысла. В имени файла `chunk_{k}.wav`, `k` обозначает k-й фрагмент в перемешанном наборе, а не k-ю реплику в исходном диалоге.

**‼️ Ваша задача — восстановить исходный хронологический порядок разговора.**

## Датасет

Каждый диалог содержит аудиофайлы `n` с именами `chunk_0.wav`, `chunk_1.wav`, …, `chunk_{n-1}.wav`. Фрагменты представляют собой отдельные реплики. Имена файлов соответствуют только перемешанному порядку. Они не указывают, где фрагмент находился в исходном разговоре. Каждый диалог содержит 7–20 фрагментов: моно, 44.1 kHz (вы можете
изменить частоту дискретизации).

**`prefix.json` содержит индексы имён файлов первых двух фрагментов каждого диалога.** Это определяет истинное начало диалога и устраняет неоднозначность между прочтением разговора в прямом и обратном порядке.

Например: `11: [7, 12]` означает, что первой и второй репликами диалога 11 являются соответственно `chunk_7.wav` и `chunk_12.wav`.

### Что вам предоставляется

Вы получаете **две папки в одинаковом формате**:

| Папка | Диалоги | `answers.json`? | Используйте её, чтобы |
|--------|-----------|-----------------|-----------|
| `dataset/train/` | 1,288 | ✅ включён | обучить / дообучить вашу модель |
| `dataset/test_public/`  | 100   | ✅ включён | запустить ваш пайплайн и самостоятельно локально вычислить результат |

Во время проверки ваша папка `dataset/test_public/` незаметно заменяется на
`hidden evaluation set` (`test_leaderboard_a` для публичной таблицы лидеров и `test_leaderboard_b` для итоговой таблицы лидеров) — они имеют тот же размер и формат, что и `dataset/test_public/`, но не содержат `answers.json`.

Ваш ноутбук снова выполняется на этих данных, а созданный им файл `answers.json` используется для оценивания. Отложенные тестовые диалоги взяты из того же распределения, что и `train`, поэтому ваш локальный результат `test_public` даёт достоверное представление о результате.

### Структура каталогов

```bash
dataset/train/
    prefix.json  # {dialogue_id: [first_idx, second_idx]} filename index 
    answers.json  # {dialogue_id: P}  ground-truth order (rank convention)
    <dialogue_id>/
        chunk_0.wav
        ...
        chunk_{n-1}.wav

dataset/test_public/
    prefix.json
    answers.json     # present only in the development copy
    <dialogue_id>/
        chunk_0.wav
        ...
        chunk_{n-1}.wav
```

## Выходные данные

Для каждого диалога определите исходный хронологический порядок его аудиофрагментов. Ваше предсказание должно быть перестановкой `P` множества `{0, 1, …, n−1}`, где `P[i]` — предсказанная хронологическая позиция `chunk_i.wav` (0 = первая).

Ваш выходной файл `answers.json` должен сопоставлять каждому идентификатору диалога предсказанную перестановку:

```json
{
  "17": [2, 0, 1],
  "42": [0, 1],
  "108": [3, 1, 0, 4, 2, 5]
}
```

### Пример

Диалог содержит 3 перемешанных фрагмента `chunk_0, chunk_1, chunk_2`:

| перемешанный фрагмент | содержание речи | истинная позиция (ранг) |
|----------------|----------------|----------------------|
| `chunk_0.wav` | *"No worries — I'll send you the notes afterwards."* | 2 (последняя) |
| `chunk_1.wav` | *"Hey, are you coming to the three o'clock meeting?"* | 0 (первая) |
| `chunk_2.wav` | *"I can't — I've got a dentist appointment then."* | 1 |

Истинный порядок — **chunk_1 → chunk_2 → chunk_0**, поэтому `P = [2, 0, 1]`, а `prefix.json` содержит `[1, 2]`.

⚠️ **P должна быть корректной перестановкой:** длина n, индексация с 0, каждое значение встречается ровно один раз. Повторяющиеся, отсутствующие или выходящие за допустимый диапазон элементы (например, при индексации с 1) дают 0 баллов за этот диалог, как и отсутствие диалога в файле. Некорректно сформированный файл или файл не в формате JSON отклоняется.

## Оценивание

Метрика этой задачи — **точность попарного упорядочивания**. Для каждой пары фрагментов проверяется: _какой из них должен идти первым?_ Пара считается правильной, если ваше предсказание даёт тот же ответ, что и эталонная разметка. Для диалога с `n` фрагментами существует $$M = n(n-1)/2$$ пар; пусть `I` — число инверсий, то есть пар, упорядоченных иначе, чем в эталонной разметке:

$$\text{score} = 1 - \frac{I}{M} \in [0, 1]$$

ℹ️ **Итоговый результат представляет собой среднее значение результатов по каждому диалогу для всех
диалогов в сплите.**

## Разрешённые модели

Для решения этой задачи как во время обучения, так и во время оценивания вы можете использовать только следующие предварительно обученные модели. Все эти модели уже загружены и доступны в среде. Примеры их использования приведены в бейзлайн-ноутбуке `solution.ipynb`. Обратите внимание, что вы не можете использовать никакие другие модели, а ваша программа не имеет доступа к интернету.

- **Представления речи:** **wav2vec 2.0**. **Энкодер Whisper** также может использоваться для извлечения признаков.
