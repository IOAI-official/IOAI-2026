# 順序を見つける

- **制限時間:** 10 分
- **環境:** GPU 1 基（≈16 GB VRAM）、インターネット接続なし
- **解答サイズ:** `solution.ipynb` ≤ 1 MB
- **ストレージ:** 5 GB 

## 問題

2 人の参加者、*Speaker A* と *Speaker B* による英語の音声対話が与えられます。各対話は話者のターンに分割されており、各ターンには一方の話者の発話のみが含まれます。各ターンは個別の `.wav` 音声ファイルとして保存されているため、完全な対話は、各ターンあたり1 つの `.wav` ファイルからなる集合として表されます。 

残念ながら、ターンはランダムにシャッフルされているため、会話はもはや意味をなしません。ファイル名 `chunk_{k}.wav` において、`k` は元の対話における k 番目のターンではなく、シャッフルされた集合における k 番目のチャンクを指します。

**‼️ あなたの課題は、会話の元の時系列順を復元することです。**

## データセット

各対話には、`chunk_0.wav`、`chunk_1.wav`、…、`chunk_{n-1}.wav` という名前の `n` 音声ファイルが含まれています。チャンクは個々のターンです。ファイル名はシャッフル後の順序に対応しています。ファイル名は、チャンクが元の会話のどこに属するかを示すものではありません。各対話には 7–20 個のチャンクがあり、モノラル、44.1 kHz です（リサンプリングしてもかまいません）。

**`prefix.json` には、各対話の最初の 2 つのチャンクのファイル名インデックスが含まれています。** これにより対話の真の開始部分が特定され、会話を前向きに読むか後ろ向きに読むかという曖昧さがなくなります。

例: `11: [7, 12]` は、対話 11 の 1 番目と 2 番目のターンが、それぞれ `chunk_7.wav` と `chunk_12.wav` であることを意味します。

### 提供されるもの

**同一形式の 2 つのフォルダ**が提供されます。

| フォルダ | 対話数 | `answers.json`? | 用途 |
|--------|-----------|-----------------|-----------|
| `dataset/train/` | 1,288 | ✅ 含まれる | モデルの訓練 / fine-tuning |
| `dataset/test_public/`  | 100   | ✅ 含まれる | パイプラインを実行し、ローカルで自己採点 |

採点時には、`dataset/test_public/` フォルダが
`hidden evaluation set`（公開リーダーボード用の `test_leaderboard_a` と最終リーダーボード用の `test_leaderboard_b`）に置き換えられます。これらは `dataset/test_public/` と同じサイズおよび形式ですが、`answers.json` は含まれていません。

そのデータ上で notebook が再度実行され、生成された `answers.json` ファイルが採点に使用されます。ホールドアウトされたテスト対話は `train` と同じ分布に由来するため、ローカルの `test_public` スコアは忠実な事前評価となります。

### ディレクトリ構造

```bash
dataset/train/
    prefix.json  # {dialogue_id: [first_idx, second_idx]} filename index 
    answers.json  # {dialogue_id: P}  ground-truth order (rank convention)
    <dialogue_id>/
        chunk_0.wav
        ...
        chunk_{n-1}.wav

dataset/test_public/
    prefix.json
    answers.json     # present only in the development copy
    <dialogue_id>/
        chunk_0.wav
        ...
        chunk_{n-1}.wav
```

## 出力

各対話について、音声チャンクの元の時系列順を求めてください。予測は `{0, 1, …, n−1}` の置換 `P` でなければなりません。ここで、`P[i]` は `chunk_i.wav` の予測された時系列上の位置です（0 = 最初）。

出力ファイル `answers.json` では、各対話 ID をその予測された置換に対応付けてください。

```json
{
  "17": [2, 0, 1],
  "42": [0, 1],
  "108": [3, 1, 0, 4, 2, 5]
}
```

### 例

ある対話には、シャッフルされた 3 個のチャンク `chunk_0, chunk_1, chunk_2` があります。

| シャッフルされたチャンク | 発話内容 | 真の位置（順位） |
|----------------|----------------|----------------------|
| `chunk_0.wav` | *"No worries — I'll send you the notes afterwards."* | 2（最後） |
| `chunk_1.wav` | *"Hey, are you coming to the three o'clock meeting?"* | 0（最初） |
| `chunk_2.wav` | *"I can't — I've got a dentist appointment then."* | 1 |

真の順序は **chunk_1 → chunk_2 → chunk_0** であるため、`P = [2, 0, 1]` となり、`prefix.json` には `[1, 2]` が格納されます。

⚠️ **P は正しい置換されたリストでなければなりません:** 長さ n、0 始まりで、各値がちょうど 1 回ずつ現れる必要があります。重複、欠損値、範囲外の要素（例: 1 始まり）がある場合、その対話のスコアは 0 になります。ファイルに含まれていない対話についても同様です。形式が不正なファイル、または JSON でないファイルは拒否されます。

## 採点

この課題の採点指標は**ペアごとの順序正解率**です。すべてのチャンクのペアについて、*どちらが先に来るべきか*を確認します。予測が正解と同じ答えを与えた場合、そのペアは正解です。`n` 個のチャンクを持つ対話には $$M = n(n-1)/2$$ 個のペアがあります。`I` を逆転数、すなわち正解とは異なる順序に並べられたペアの数とします。

$$\text{score} = 1 - \frac{I}{M} \in [0, 1]$$

ℹ️ **最終スコアは、その分割内のすべての対話について、対話ごとのスコアを平均したものです。**

## 使用可能なモデル

訓練時と評価時の両方において、この課題を解くために使用できる事前訓練済みモデルは以下のものだけです。これらのモデルはすべて、すでにダウンロードされ、環境内で利用可能です。ベースライン notebook `solution.ipynb` で使用例を確認できます。他のモデルは使用できず、プログラムはインターネットにアクセスできないことに注意してください。

- **音声表現:** **wav2vec 2.0**。**Whisper エンコーダー**も特徴抽出器として使用できます。
[wav2vec モデルカード](https://yastatic.net/s3/contest/ioai/1/01_facebook_wav2vec2-base-960h_MODEL_CARD.html)

- **自動音声認識（ASR）:** **OpenAI Whisper**（任意のサイズ）。
[Whisper モデルカード](https://yastatic.net/s3/contest/ioai/1/03_openai_whisper-small_MODEL_CARD.html)
- **言語モデル:** **Qwen2.5-0.5B**。zero-shot で使用することも、提供された `train` 分割で fine-tuning して使用することもできます。
[Qwen モデルカード](https://yastatic.net/s3/contest/ioai/1/02_Qwen_Qwen2.5-0.5B_MODEL_CARD.html)

**10 分の制限時間には、採点時に行う訓練または fine-tuning と、評価セットに対する推論の両方が含まれなければならないことに注意してください。**
