# CI/CD для проверки решений

Решения участников будут проверяться с использованием CI/CD-пайплайна в этом репозитории.

Конфигурация CI расположена в файле [`.gitlab-ci.yml`](.gitlab-ci.yml).

## Общая схема работы

- В кубике `test` решение участника клонируется в директорию `$REPO_NAME` (обычная задача) или скачивается в директорию `solution` из `$RUN_URL` (задача без пользовательского репозитория)
- Вам необходимо доработать этот кубик, включив туда флоу проверки
- Результат тестирования необходимо записать в файл `report.json`.
- В случае падения кубика `test` кубик `send_crash` отправит вердикт Crash в Контест.

## Системные требования

В каждый Job необходимо добавить ключ `tags` с указанием тега раннера, на котором будут запускаться проверки.

Для выполнения кубика `test` на раннере должны быть установлены Git и Git LFS. В примере утилиты устанавливаются
на Alpine Linux в каждом запуске. Если они уже будут доступны на раннерах, установка вручную необязательна.

## Ограничения

Максимальная длительность работы pipeline — 5 часов. После этого в Контесте автоматически выставится вердикт Crash, дальнейшая отправка отчёта будет невозможна.

## Безопасность запусков

Если вы запускаете код участников, участники могут делать то, что вы не ожидаете. Например, отправлять приватные тесты в интернет, пытаться читать токены.

В кубике `test` удаляются некоторые переменные окружения с чувствительными секретами. Будьте аккуратны и не удаляйте этот фрагмент кода. Тем не менее, даже после удаления существуют способы извлечь значения этих переменных.

Для запуска недоверенного кода мы настоятельно рекомендуем использовать Docker или другие средства контейнеризации.

## Формат файла `report.json`

\* — обязательное поле

| Ключ | Тип | Описание |
|------|-----|----------|
| `report` | `object`* | Отчёт о тестировании |
| `report.verdict` | `string` | Ошибка запуска решения. Указывается **только** в случае, когда тестов нет. Может принимать значения `CompilationError`, `PrecompileCheckFailed` или `Crash`. Если хотя бы один тест указан, то в качестве вердикта посылки используется вердикт первого проваленного теста. |
| `report.result` | `object` | Балл за посылку. Указывается для мониторов типа SCORING и CALCULATOR. |
| `report.result.score` | `number` | Балл за посылку в мониторе SCORING. Вещественное число. |
| `report.result.message` | `string` | JSON-сериализованные баллы за посылку в мониторе CALCULATOR. Не используйте без согласования с командой Контеста. |
| `report.tests` | `array`* | Список тестов. Возможно, пустой, если заполнен `report.verdict`. |
| `report.tests[*].testName` | `string`* | Имя теста. Должно быть уникальным. Показывается в интерфейсе администратора. |
| `report.tests[*].testsetName` | `string`* | Набор тестов. Если `samples`, является тестом из примера — это может влиять на настройки показа отчёта. |
| `report.tests[*].verdict` | `string`* | Вердикт. Возможные значения: `OK`, `WrongAnswer`, `PresentationError`, `TimeLimitExceeded`, `MemoryLimitExceeded`, `IdlenessLimitExceeded`, `OutputLimitExceeded`, `RuntimeError`, `Crash` |
| `report.tests[*].score` | `number` | Балл за тест. Отображается в колонке «Баллы». Используется для оценивания только в мониторе SCORING, если `report.result` не задан. |
| `report.tests[*].runningTime` | `number` | Время работы решения в миллисекундах. |
| `report.tests[*].memoryUsed` | `number` | Затраченная память в байтах. |
| `artifacts` | `array` | Артефакты. Позволяют добавить к тестам произвольные файлы, которые можно скачать в интерфейсе администратора и в интерфейсе участника, если это разрешено настройками контеста. |
| `artifacts[*].testName` | `string`* | Имя теста, к которому нужно прикрепить артефакт. Должно совпасть с одним из `report.tests[*].testName`. |
| `artifacts[*].testDataType` | `string`* | Тип артефакта. Возможные значения: `INPUT`, `OUTPUT`, `ANSWER`, `ERROR`, `CHECKER_ERROR`. |
| `artifacts[*].path` | `string`* | Путь к файлу для загрузки. |

Пример файла:

```json
{
  "artifacts": [
    {"testName": "test1", "testDataType": "INPUT",  "path": "artifacts/test1-input.txt"},
    {"testName": "test1", "testDataType": "OUTPUT", "path": "artifacts/test1-output.txt"},
    {"testName": "test1", "testDataType": "ANSWER", "path": "artifacts/test1-answer.txt"},
    {"testName": "test2", "testDataType": "ERROR",  "path": "artifacts/test2-error.txt"}
  ],
  "report": {
    "result": {"score": 70.0},
    "tests": [
      {"testName": "test1", "testsetName": "samples", "verdict": "OK", "score": 30.0, "runningTime": 1500, "memoryUsed": 32768},
      {"testName": "test2", "testsetName": "tests",   "verdict": "OK", "score": 0.0,  "runningTime": 3500, "memoryUsed": 65536},
      {"testName": "test3", "testsetName": "tests",   "verdict": "OK", "score": 40.0, "runningTime": 6500, "memoryUsed": 71680}
    ]
  }
}
```

Вместо готового кубика от нашей команды вы можете отправлять решения в Контест самостоятельно. Для этого:
- с помощью эндпоинта [`/v2/gitlab/upload-artifact`](https://api.contest.yandex.net/api/public/swagger-ui.html#/public-gitlab-controller/uploadArtifactUsingPOST) получите ссылки для загрузки артефактов и загрузите по ним файлы методом PUT
- после этого с помощью эндпоинта [`/v2/gitlab/report`](https://api.contest.yandex.net/api/public/swagger-ui.html#/public-gitlab-controller/submitReportUsingPOST) загрузите содержимое отчёта

## Доступные переменные окружения

### Обычная задача (с репозиторием участника)

| Переменная         | Описание                                        |
|--------------------|-------------------------------------------------|
| `REPO_PATH`        | Путь до репозитория с решением участника        |
| `REPO_NAME`        | Имя директории с решением участника             |
| `PARTICIPATION_ID` | ID репозитория пользователя в Контесте          |
| `RUN_ID`           | ID посылки пользователя в Контесте              |
| `COMMIT_ID`        | Хэш коммита решения пользователя                |
| `PUBLIC_API`       | Адрес публичного API Контеста                   |
| `JWT_TOKEN`        | Токен для отправки результатов в Контест        |
| `PROJECT_TOKEN`    | Токен с правами доступа к репозиторию участника |



### Задача без пользовательского репозитория

| Переменная      | Описание                                                                       |
|-----------------|--------------------------------------------------------------------------------|
| `REPO_NAME`     | Имя директории для скачанного решения (в пайплайне всегда `submission-source`) |
| `RUN_ID`        | ID посылки пользователя в Контесте                                             |
| `PUBLIC_API`    | Адрес публичного API Контеста                                                  |
| `JWT_TOKEN`     | Токен для отправки результатов в Контест                                       |
| `RUN_URL`       | URL эндпоинта скачивания исходника посылки                                     |
| `FILENAME`      | Имя файла посылки участника                                                    |
