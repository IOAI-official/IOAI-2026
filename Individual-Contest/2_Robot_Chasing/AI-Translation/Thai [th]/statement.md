# การไล่ตามของหุ่นยนต์

- **เวลาจำกัด:** 5 นาที
- **สภาพแวดล้อม:** GPU หนึ่งตัว (VRAM ≈16 GB), ไม่มีอินเทอร์เน็ต
- **ขนาดโซลูชัน:** `solution.ipynb` ≤ 1 MB
- **พื้นที่จัดเก็บ:** 5 GB 

## งาน

มีหุ่นยนต์หกตัว หุ่นยนต์แต่ละตัวทำงานในห้องขนาดเล็กที่แทนด้วยกริด แต่ละห้องมีพื้นที่ที่เล่นได้ขนาด `6×6` ซึ่งล้อมรอบด้วยกำแพง ดังนั้นอาร์เรย์ `image` เต็มจึงมีขนาด `8×8` (พื้นที่ที่เล่นได้ + กำแพง)

หุ่นยนต์แต่ละตัวได้รับคำสั่งภาษาอังกฤษที่อธิบายงานหนึ่ง สแนปช็อตอาจถูกถ่าย ณ จุดใดก็ได้ขณะที่หุ่นยนต์กำลังปฏิบัติงานนั้น เป้าหมายของคุณคือทำนายการกระทำถัดไปของหุ่นยนต์

หุ่นยนต์ไม่ได้เดินตามเส้นทางที่สั้นที่สุดเสมอไป หุ่นยนต์ 0 อาจมีพฤติกรรมแตกต่างจากหุ่นยนต์ 1 แต่หุ่นยนต์แต่ละตัวจะปฏิบัติตามแบบแผนของตนเองอย่างสม่ำเสมอ ใช้ตัวอย่างฝึกซึ่งมีการกระทำถัดไปที่ถูกต้องรวมอยู่ด้วยเพื่อเรียนรู้แบบแผนเหล่านี้

![หุ่นยนต์](../../robot.jpg)

ภารกิจมีสามประเภท:

- **ไปยัง** วัตถุ เช่น `"approach the red ball"`;
- **หยิบ** วัตถุ เช่น `"grab the blue key"`;
- **วางวัตถุชิ้นหนึ่งไว้ถัดจากอีกชิ้นหนึ่ง** เช่น
  `"place the red box beside the green ball"`.

คำสั่งเดียวกันสามารถเขียนได้หลายแบบ ชุดทดสอบอาจมีการผสมแบบใหม่ของวลี สี และประเภทวัตถุที่คุ้นเคย อย่างไรก็ตาม ทุกคำ รูปแบบวลี สี ประเภทวัตถุ และประเภทภารกิจที่ใช้ในชุดทดสอบจะปรากฏในชุดฝึกด้วย

แต่ละตัวอย่างมีฟิลด์ต่อไปนี้:

| ฟิลด์ | ความหมาย |
|---|---|
| `robot_id` | ระบุว่าเป็นหุ่นยนต์ตัวใดในบรรดาหุ่นยนต์ 6 ตัว (`0`–`5`) |
| `image` | ห้อง ซึ่งเป็นอาร์เรย์จำนวนเต็ม `8×8×2` โดยแชนเนล 0 เก็บ object_idx เชิงหมวดหมู่ (เช่น 1=ว่าง, 2=กำแพง, 10=หุ่นยนต์) และแชนเนล 1 เก็บ colour_idx เชิงหมวดหมู่ (0–5) |
| `direction` | ทิศทางที่หุ่นยนต์กำลังหันหน้าอยู่ |
| `mission` | คำสั่งภาษาธรรมชาติที่มองเห็นได้ |
| `carrying` | `null` หรือ `[object_idx, colour_idx]` สำหรับวัตถุที่กำลังถืออยู่ |

แต่ละแถวเป็นสแนปช็อตอิสระที่เรียงลำดับแบบสุ่ม แถวเหล่านี้ไม่ได้ประกอบกันเป็นเอพิโสด และไม่มีการสังเกตหรือการกระทำก่อนหน้าให้ใช้ในเวลาประเมินผล

`visualize_dataset.ipynb` ที่ให้มาช่วยให้คุณตรวจสอบการสังเกตที่โมเดลใช้ได้ในสถานการณ์ต่าง ๆ

## การเข้ารหัสกริด

`image[row][column] = [object_idx, colour_idx]` ดัชนีแรกคือแถวจากบนลงล่าง และดัชนีที่สองคือคอลัมน์จากซ้ายไปขวา อาร์เรย์รวมขอบกำแพงด้านนอก ดังนั้นพื้นที่ภายในที่เคลื่อนที่ได้คือ `6×6`

รหัสวัตถุ:

| id | วัตถุ |
|---:|---|
| 1 | เซลล์ว่าง |
| 2 | กำแพง |
| 5 | กุญแจ |
| 6 | ลูกบอล |
| 7 | กล่อง |
| 10 | หุ่นยนต์ |
| 11 | token |

token อาจปรากฏในห้อง แต่จะไม่ถูกกล่าวถึงในภารกิจ

รหัสสีคือ `0` แดง, `1` เขียว, `2` น้ำเงิน, `3` ม่วง, `4` เหลือง และ `5` เทา แชนเนลสีไม่มีความหมายสำหรับเซลล์ว่างและกำแพง

ภาพมีเพียงสองแชนเนลข้างต้น ทิศทางของหุ่นยนต์ถูกระบุไว้หนึ่งครั้งในฟิลด์ `direction` ระดับบนสุด โดยไม่ได้ทำซ้ำภายใน `image`

## การกระทำ

สำหรับรหัส `0`–`3` การกระทำเพื่อเคลื่อนที่ใช้การจับคู่แบบสัมบูรณ์ดังต่อไปนี้:

| การกระทำ | ความหมาย |
|---:|---|
| 0 | เคลื่อนขึ้น |
| 1 | เคลื่อนลง |
| 2 | เคลื่อนไปทางซ้าย |
| 3 | เคลื่อนไปทางขวา |
| 4 | หยิบ |
| 5 | วาง |


ฟิลด์ `direction` ระบุทิศทางที่กำลังหันหน้าอยู่โดยใช้: 0 = ขึ้น (row - 1), 1 = ลง (row + 1), 2 = ซ้าย (col - 1), 3 = ขวา (col + 1)

การกระทำเพื่อเคลื่อนที่จะหันหุ่นยนต์ไปยังทิศทางสัมบูรณ์นั้นก่อน แล้วจึงพยายามเคลื่อนหุ่นยนต์ไปหนึ่งเซลล์ กำแพงหรือวัตถุอาจขวางการเคลื่อนที่ แต่ทิศทางยังคงเปลี่ยน `pick up` และ `drop` กระทำต่อเซลล์เป้าหมายที่อยู่ติดกันซึ่งกำหนดโดยทิศทางเท่านั้น (เช่น หาก direction=0 การกระทำนั้นจะกระทำต่อ (row - 1, col))

## ชุดข้อมูล

คุณจะได้รับสองโฟลเดอร์:

| โฟลเดอร์ | แถว | `labels.json`? | ใช้เพื่อ |
|---|---:|---|---|
| `dataset/train/` | 60,000 | มีให้ | ฝึกโมเดลของคุณ |
| `dataset/test_public/` | 3,600 | มีให้ในสำเนาสำหรับการพัฒนา | เรียกใช้และให้คะแนนไปป์ไลน์ของคุณด้วยตนเอง |

แต่ละโฟลเดอร์มี `observations.json` ซึ่งเป็นลิสต์ JSON ของตัวอย่างที่อธิบายไว้
ข้างต้น `labels.json` เป็นลิสต์ JSON ของการกระทำ (`0`–`5`) ที่สอดคล้องกัน

ชุดฝึกมีจำนวนแถวต่อหุ่นยนต์เท่ากับ 10,000 แถวพอดี และมี 20,000 แถวจากแต่ละ
กลุ่มงาน ชุดทดสอบสาธารณะมี 600 แถวต่อหุ่นยนต์ ครอบ `image` ด้วย
`numpy.asarray(...)` หากคุณต้องการอาร์เรย์

ในเวลาตรวจให้คะแนน `dataset/test_public/` จะถูกแทนที่โดยอัตโนมัติด้วยชุดที่ซ่อนไว้ซึ่งมี
การสังเกต 3,600 รายการในรูปแบบเดียวกัน แต่ไม่มี `labels.json` กระดานผู้นำ
สาธารณะใช้ `test_leaderboard_a`; การจัดอันดับสุดท้ายใช้
`test_leaderboard_b` โน้ตบุ๊กที่อ่านป้ายกำกับของชุดทดสอบโดยไม่มีเงื่อนไขจะล้มเหลว
ให้อ่านป้ายกำกับจาก `dataset/train/` เท่านั้น

## เอาต์พุต

เขียน `predictions.json` ลงในไดเรกทอรีทำงานของโน้ตบุ๊ก ไฟล์นี้ต้องเป็นลิสต์ JSON
ที่มีการกระทำซึ่งเป็นจำนวนเต็มหนึ่งค่า (`0`–`5`) ต่อหนึ่งแถวของ
`dataset/test_public/observations.json` ตามลำดับเดิม สำหรับชุดทดสอบสมมุติที่มีหกตัวอย่าง เอาต์พุตที่ถูกต้องอาจเป็น:

```json
[0, 3, 2, 2, 5, 4]
```

ไฟล์ JSON ที่หายไปหรือไม่ถูกต้อง จำนวนผลการทำนายที่ไม่ถูกต้อง ค่าที่ไม่ใช่จำนวนเต็ม
หรือการกระทำที่อยู่นอก `{0,1,2,3,4,5}` จะถูกปฏิเสธโดยไม่ได้รับคะแนน

## การให้คะแนน

การให้คะแนนใช้ **ค่าเฉลี่ยความแม่นยำรายหุ่นยนต์** บนสเกล `0`–`100` โดยจะคำนวณความแม่นยำ
แยกกันสำหรับหุ่นยนต์แต่ละตัวก่อน แล้วจึงหาค่าเฉลี่ยจากหุ่นยนต์ทั้งหกตัว ดังนั้น
หุ่นยนต์ทุกตัวจึงมีน้ำหนักเท่ากัน
