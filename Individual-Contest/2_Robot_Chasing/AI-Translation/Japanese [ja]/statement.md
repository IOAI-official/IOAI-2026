# ロボット追跡

- **制限時間:** 5分
- **環境:** 単一のGPU（≈16 GB VRAM）、インターネットなし
- **解答サイズ:** `solution.ipynb` ≤ 1 MB
- **ストレージ:** 5 GB 

## タスク

6体のロボットがいます。各ロボットは、グリッドで表された小さな部屋の中で動作します。各部屋には、壁で囲まれた `6×6` のプレイ可能領域があるため、完全な `image` 配列のサイズは `8×8`（プレイ可能領域 + 壁）です。

各ロボットは、タスクを説明する英語の指示を受け取ります。スナップショットは、ロボットがその指示を実行している間の任意の時点で取得される可能性があります。皆さんの目標は、ロボットの次の行動を予測することです。

ロボットは必ずしも最短経路に従うとは限りません。ロボット 0 はロボット 1 とは異なる行動をする場合がありますが、各ロボットはそれぞれ一貫した固有のパターンに従います。正しい次の行動を含む訓練例を使用して、これらのパターンを学習してください。

![ロボット](../../robot.jpg)

ミッションには3種類あります。

- ある物体のところへ**行く**。たとえば `"approach the red ball"`。
- ある物体を**拾う**。たとえば `"grab the blue key"`。
- **ある物体を別の物体の隣に置く**。たとえば
  `"place the red box beside the green ball"`。

同じ指示が複数の表現で書かれることがあります。テストセットには、既知のフレーズ、色、および物体の種類の新しい組み合わせが含まれる場合があります。ただし、テストセットで使用されるすべての単語、フレーズパターン、色、物体の種類、およびミッションの種類は、訓練セットにも現れます。

各サンプルには、次のフィールドがあります。

| フィールド | 意味 |
|---|---|
| `robot_id` | 6体のうちどのロボットであるか（`0`–`5`） |
| `image` | 部屋を表す `8×8×2` 整数配列。チャネル 0 にはカテゴリ値 object_idx（たとえば 1=空き、2=壁、10=ロボット）が格納され、チャネル 1 にはカテゴリ値 colour_idx（0–5）が格納されます。 |
| `direction` | ロボットが現在向いている方向 |
| `mission` | 表示されている自然言語の指示 |
| `carrying` | 運んでいる物体を表す `null` または `[object_idx, colour_idx]` |

各行は、ランダムな順序で並べられた独立したスナップショットです。これらはエピソードを構成せず、評価時には以前の観測や行動を利用できません。

提供されている `visualize_dataset.ipynb` を使用すると、さまざまな状況でモデルが利用できる観測を確認できます。

## グリッドのエンコーディング

`image[row][column] = [object_idx, colour_idx]`。第1インデックスは上から下への行、第2インデックスは左から右への列です。この配列には外周の壁が含まれるため、移動可能な内部領域は `6×6` です。

物体のid：

| id | 物体 |
|---:|---|
| 1 | 空きマス |
| 2 | 壁 |
| 5 | 鍵 |
| 6 | ボール |
| 7 | 箱 |
| 10 | ロボット |
| 11 | トークン |

部屋にはトークンが現れる場合がありますが、ミッションで名前が挙げられることはありません。

色のidは、`0` 赤、`1` 緑、`2` 青、`3` 紫、`4` 黄、`5` グレーです。空きマスと壁については、色チャネルに意味はありません。

画像には、上記の2つのチャネルしかありません。ロボットの方向は、トップレベルの `direction` フィールドで1度だけ提供され、`image` 内には重複して含まれません。

## 行動

コード `0`–`3` について、移動行動は次の絶対方向の対応を使用します。

| 行動 | 意味 |
|---:|---|
| 0 | 上に移動 |
| 1 | 下に移動 |
| 2 | 左に移動 |
| 3 | 右に移動 |
| 4 | 拾う |
| 5 | 置く |


`direction` フィールドは、現在向いている方向を次の値で示します：0 = 上（row - 1）、1 = 下（row + 1）、2 = 左（col - 1）、3 = 右（col + 1）。

移動行動では、まずロボットがその絶対方向を向き、次に1マス移動しようとします。壁または物体によって移動が妨げられる場合がありますが、それでも向きは変わります。`pick up` と `drop` は、方向によって定義される隣接した対象マスにのみ作用します（たとえば direction=0 の場合、(row - 1, col) に作用します）。

## データセット

2つのフォルダが提供されます。

| フォルダ | 行数 | `labels.json`? | 用途 |
|---|---:|---|---|
| `dataset/train/` | 60,000 | 含まれる | モデルを訓練する |
| `dataset/test_public/` | 3,600 | 開発用コピーには含まれる | パイプラインを実行して自己採点する |

各フォルダには、上記のサンプルを格納したJSONリストである `observations.json` が含まれます。`labels.json` は、対応する行動（`0`–`5`）を格納したJSONリストです。

訓練セットには、ロボットごとに正確に 10,000 行、各タスクファミリーから 20,000 行が
含まれます。公開テストには、ロボットごとに 600 行が含まれます。配列が必要な場合は、`image` を
`numpy.asarray(...)` でラップしてください。

採点時には、`dataset/test_public/` は、同じ形式で `labels.json` を含まない
3,600 件の観測からなる非公開セットに透過的に置き換えられます。公開
リーダーボードでは `test_leaderboard_a` が使用され、最終順位では
`test_leaderboard_b` が使用されます。テストラベルを無条件に読み込むnotebookは失敗します。
ラベルは `dataset/train/` からのみ読み込んでください。

## 出力

notebookの作業ディレクトリに `predictions.json` を書き込んでください。これは、`dataset/test_public/observations.json` の
各行に対して、同じ順序で1つの整数の行動（`0`–`5`）を含むJSON
リストでなければなりません。6個のサンプルを含む仮想的なテストセットに対する有効な出力は、次のようになります。

```json
[0, 3, 2, 2, 5, 4]
```

JSONファイルが存在しないか無効である場合、予測数が正しくない場合、整数でない値がある場合、
または `{0,1,2,3,4,5}` の範囲外の行動がある場合、スコアは付与されず却下されます。

## 採点

スコアは、`0`–`100` の尺度における**ロボットごとの正解率の平均**です。正解率は最初に
各ロボットについて個別に計算され、その後6体すべてのロボットについて平均されます。したがって、すべての
ロボットの重みは等しくなります。

## 提出方法

1. `solution.ipynb` を開き、すべてのセルを実行します。
2. 公開テストセットに対する 3,600 件の予測を含む `predictions.json` が書き込まれることを
   確認します。
3. 必要であればモデルを改善してください。提供されているbaselineは、必要な
   入出力形式を示すだけのものです。
4. JupyterLabのGitタブで `solution.ipynb` をステージしてコミットし、その後pushします。
5. Contestページに戻り、**Submit**をクリックします。

`solution.ipynb` という名前のファイルを正確に1つ提出してください。
