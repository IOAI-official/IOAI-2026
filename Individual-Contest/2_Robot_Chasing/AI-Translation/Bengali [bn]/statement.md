# রোবটের ধাওয়া

- **সময়সীমা:** 5 minutes
- **পরিবেশ:** একটি GPU (≈16 GB VRAM), ইন্টারনেট নেই
- **সমাধানের আকার:** `solution.ipynb` ≤ 1 MB
- **স্টোরেজ:** 5 GB 

## কাজ

ছয়টি রোবট রয়েছে। প্রতিটি রোবট একটি গ্রিড দ্বারা উপস্থাপিত ছোট ঘরে কাজ করে। প্রতিটি ঘরে দেয়াল দিয়ে ঘেরা একটি `6×6` খেলার উপযোগী অঞ্চল রয়েছে, তাই সম্পূর্ণ `image` অ্যারের আকার `8×8` (খেলার উপযোগী অঞ্চল + দেয়াল)।

প্রতিটি রোবট একটি কাজের বর্ণনাসংবলিত ইংরেজি নির্দেশনা পায়। রোবটটি কাজটি সম্পাদন করার সময় যেকোনো মুহূর্তে স্ন্যাপশট নেওয়া হতে পারে। আপনার লক্ষ্য হলো রোবটটির পরবর্তী অ্যাকশন অনুমান করা।

রোবটগুলি সব সময় সংক্ষিপ্ততম পথ অনুসরণ করে না। Robot 0-এর আচরণ Robot 1-এর চেয়ে ভিন্ন হতে পারে, তবে প্রতিটি রোবট তার নিজস্ব সামঞ্জস্যপূর্ণ ধরন অনুসরণ করে। এই ধরনগুলি শেখার জন্য সঠিক পরবর্তী অ্যাকশনসহ ট্রেনিং উদাহরণগুলি ব্যবহার করুন।

![রোবট](../../robot.jpg)

তিন ধরনের মিশন রয়েছে:

- কোনো বস্তুর কাছে **যাওয়া**, যেমন `"approach the red ball"`;
- কোনো বস্তু **তুলে নেওয়া**, যেমন `"grab the blue key"`;
- **একটি বস্তু অন্যটির পাশে রাখা**, যেমন
  `"place the red box beside the green ball"`।

একই নির্দেশনা একাধিকভাবে লেখা হতে পারে। টেস্ট সেটে পরিচিত বাক্যাংশ, রং ও অবজেক্ট টাইপের নতুন সমন্বয় থাকতে পারে। তবে টেস্ট সেটে ব্যবহৃত প্রতিটি শব্দ, বাক্যাংশের ধরন, রং, অবজেক্ট টাইপ ও মিশনের ধরন ট্রেনিং সেটেও উপস্থিত রয়েছে।

প্রতিটি স্যাম্পলে নিম্নলিখিত ফিল্ডগুলি রয়েছে:

| ফিল্ড | অর্থ |
|---|---|
| `robot_id` | এটি 6টি রোবটের মধ্যে কোনটি (`0`–`5`) |
| `image` | ঘরটি, একটি `8×8×2` পূর্ণসংখ্যার অ্যারে, যেখানে channel 0-তে শ্রেণিগত object_idx (যেমন, 1=খালি, 2=দেয়াল, 10=রোবট) এবং channel 1-এ শ্রেণিগত colour_idx (0–5) থাকে। |
| `direction` | রোবটটি বর্তমানে যে দিকে মুখ করে আছে |
| `mission` | দৃশ্যমান স্বাভাবিক-ভাষার নির্দেশনা |
| `carrying` | বহন করা বস্তুর জন্য `null` অথবা `[object_idx, colour_idx]` |

সারিগুলি এলোমেলো ক্রমে থাকা স্বতন্ত্র স্ন্যাপশট। এগুলি episode গঠন করে না এবং মূল্যায়নের সময় পূর্ববর্তী কোনো observation বা action পাওয়া যায় না।

প্রদত্ত `visualize_dataset.ipynb` ব্যবহার করে আপনি বিভিন্ন পরিস্থিতিতে model-এর কাছে উপলভ্য observationগুলি পরিদর্শন করতে পারবেন।

## গ্রিড এনকোডিং

`image[row][column] = [object_idx, colour_idx]`। প্রথম index হলো ওপর থেকে নিচ পর্যন্ত row এবং দ্বিতীয়টি হলো বাঁ থেকে ডান পর্যন্ত column। অ্যারেটিতে বাইরের দেয়ালের সীমানা অন্তর্ভুক্ত রয়েছে, তাই চলাচলযোগ্য অভ্যন্তরভাগ হলো `6×6`।

অবজেক্ট id:

| id | অবজেক্ট |
|---:|---|
| 1 | খালি cell |
| 2 | দেয়াল |
| 5 | চাবি |
| 6 | বল |
| 7 | বাক্স |
| 10 | রোবট |
| 11 | token |

ঘরে token থাকতে পারে, তবে মিশনে কখনো সেগুলির নাম উল্লেখ করা হয় না।

রঙের id হলো `0` লাল, `1` সবুজ, `2` নীল, `3` বেগুনি, `4` হলুদ এবং `5` ধূসর। খালি cell এবং দেয়ালের ক্ষেত্রে colour channel-এর কোনো অর্থ নেই।

ছবিটিতে শুধু ওপরের দুটি channel রয়েছে। রোবটের দিকটি শীর্ষ-স্তরের `direction` ফিল্ডে একবার দেওয়া হয়; এটি `image`-এর ভেতরে পুনরায় দেওয়া হয় না।

## অ্যাকশন

`0`–`3` কোডের জন্য চলাচলের অ্যাকশনগুলি নিম্নলিখিত পরম ম্যাপিং ব্যবহার করে:

| অ্যাকশন | অর্থ |
|---:|---|
| 0 | ওপরে যাওয়া |
| 1 | নিচে যাওয়া |
| 2 | বাঁ দিকে যাওয়া |
| 3 | ডান দিকে যাওয়া |
| 4 | তুলে নেওয়া |
| 5 | নামিয়ে রাখা |


`direction` ফিল্ডটি বর্তমান মুখ করার অভিমুখ নির্দেশ করে: 0 = ওপর (row - 1), 1 = নিচ (row + 1), 2 = বাঁ (col - 1), 3 = ডান (col + 1)।

একটি চলাচলের অ্যাকশন প্রথমে রোবটটিকে সেই পরম দিকে ঘোরায় এবং তারপর সেটিকে এক cell সরানোর চেষ্টা করে। কোনো দেয়াল বা বস্তু চলাচলটি বাধা দিতে পারে, কিন্তু দিক তবুও পরিবর্তিত হয়। `pick up` এবং `drop` দিক দ্বারা নির্ধারিত সংলগ্ন target cell-এর ওপরই একচেটিয়াভাবে কাজ করে (যেমন, direction=0 হলে এটি (row - 1, col)-এর ওপর কাজ করে)।

## ডেটাসেট

আপনি দুটি folder পাবেন:

| Folder | সারি | `labels.json`? | এটি যে কাজে ব্যবহার করবেন |
|---|---:|---|---|
| `dataset/train/` | 60,000 | অন্তর্ভুক্ত | আপনার model ট্রেন করতে |
| `dataset/test_public/` | 3,600 | development copy-তে অন্তর্ভুক্ত | আপনার pipeline চালাতে ও নিজে স্কোর করতে |

প্রতিটি folder-এ `observations.json` রয়েছে, যা ওপরে বর্ণিত স্যাম্পলগুলির একটি JSON list।
`labels.json` হলো অ্যাকশনগুলির (`0`–`5`) একটি সারিবদ্ধ JSON list।

ট্রেনিং সেটে প্রতি রোবটের জন্য ঠিক 10,000টি সারি এবং প্রতিটি
task family থেকে 20,000টি সারি রয়েছে। পাবলিক টেস্টে প্রতি রোবটের জন্য 600টি সারি রয়েছে। আপনার একটি array প্রয়োজন হলে `image`-কে
`numpy.asarray(...)` দিয়ে আবৃত করুন।

গ্রেডিংয়ের সময় `dataset/test_public/` স্বচ্ছভাবে একই ফরম্যাটের
3,600টি observation-এর একটি গোপন সেট দিয়ে প্রতিস্থাপিত হয়, তবে এতে `labels.json` থাকে না। পাবলিক
leaderboard-এ `test_leaderboard_a` ব্যবহৃত হয়; চূড়ান্ত ranking-এ ব্যবহৃত হয়
`test_leaderboard_b`। যে notebook নিঃশর্তভাবে test label পড়ে, সেটি ব্যর্থ হবে।
শুধু `dataset/train/` থেকে label পড়ুন।

## আউটপুট

নোটবুকের working directory-তে `predictions.json` লিখুন। এটি অবশ্যই একটি JSON
list হতে হবে, যাতে `dataset/test_public/observations.json`-এর প্রতিটি সারির জন্য একই ক্রমে একটি করে পূর্ণসংখ্যার অ্যাকশন (`0`–`5`) থাকে।
ছয়টি স্যাম্পলসংবলিত একটি কাল্পনিক টেস্ট সেটের জন্য বৈধ আউটপুট হবে:

```json
[0, 3, 2, 2, 5, 4]
```

অনুপস্থিত বা অবৈধ JSON file, ভুলসংখ্যক prediction, অ-পূর্ণসংখ্যা মান,
অথবা `{0,1,2,3,4,5}`-এর বাইরের কোনো অ্যাকশন স্কোর না দিয়েই প্রত্যাখ্যান করা হবে।

## স্কোরিং

স্কোরিং হলো `0`–`100` স্কেলে **প্রতি-রোবট সঠিকতার হারের গড়**। প্রথমে প্রতিটি রোবটের জন্য
স্বতন্ত্রভাবে সঠিকতার হার গণনা করা হয়, তারপর ছয়টি রোবটের ওপর তার গড় নেওয়া হয়। তাই প্রতিটি
রোবটের ওজন সমান।
