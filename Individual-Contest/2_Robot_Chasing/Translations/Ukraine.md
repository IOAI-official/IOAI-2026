# Переслідування роботів

- **Обмеження часу:** 5 хвилин
- **Середовище:** один GPU (≈16 GB VRAM), без інтернету
- **Розмір розв’язку:** `solution.ipynb` ≤ 1 MB
- **Сховище:** 5 GB 

## Завдання

Є шість роботів. Кожен робот діє в невеликій кімнаті, представленій сіткою. Кожна кімната має ігрову область `6×6`, оточену стінами, тому повний масив `image` має розмір `8×8` (ігрова область + стіни).

Кожен робот отримує інструкцію англійською мовою, що описує завдання. Знімок може бути зроблений у будь-який момент, поки робот його виконує. Ваша мета — передбачити наступну дію робота.

Роботи не завжди рухаються найкоротшим шляхом. Робот 0 може поводитися інакше, ніж Робот 1, але кожен робот дотримується власної сталої закономірності. Використайте тренувальні приклади, які містять правильні наступні дії, щоб вивчити ці закономірності.

![Робот](../robot.jpg)

Є три типи місій:

- **дійти до** предмета, наприклад `"approach the red ball"`;
- **підібрати** предмет, наприклад `"grab the blue key"`;
- **покласти один предмет поруч з іншим**, наприклад
  `"place the red box beside the green ball"`.

Ту саму інструкцію можна сформулювати кількома способами. Тестовий набір може містити нові комбінації знайомих фраз, кольорів і типів предметів. Однак кожне слово, шаблон фрази, колір, тип предмета й тип місії, використані в тестовому наборі, також трапляються в тренувальному наборі.

Кожен зразок має такі поля:

| Поле | Значення |
|---|---|
| `robot_id` | який із 6 роботів це є (`0`–`5`) |
| `image` | кімната — цілочисельний масив `8×8×2`, у якому канал 0 містить категоріальний object_idx (наприклад, 1=порожньо, 2=стіна, 10=робот), а канал 1 містить категоріальний colour_idx (0–5). |
| `direction` | напрямок, у якому робот зараз зорієнтований |
| `mission` | видима інструкція природною мовою |
| `carrying` | `null` або `[object_idx, colour_idx]` для предмета, який переноситься |

Рядки є незалежними знімками у випадковому порядку. Вони не утворюють епізодів, і під час оцінювання немає доступу до попереднього спостереження чи дії.

Наданий `visualize_dataset.ipynb` дає змогу переглядати спостереження, доступні моделі в різних ситуаціях.

## Кодування сітки

`image[row][column] = [object_idx, colour_idx]`. Перший індекс — це рядок згори вниз, а другий — стовпець зліва направо. Масив містить зовнішню межу зі стін, тому внутрішня область, якою можна пересуватися, має розмір `6×6`.

Ідентифікатори предметів:

| id | предмет |
|---:|---|
| 1 | порожня клітинка |
| 2 | стіна |
| 5 | ключ |
| 6 | м’яч |
| 7 | коробка |
| 10 | робот |
| 11 | токен |

Токени можуть бути в кімнаті, але їх ніколи не називають у місіях.

Ідентифікатори кольорів: `0` — червоний, `1` — зелений, `2` — синій, `3` — фіолетовий, `4` — жовтий і `5` — сірий. Канал кольору не має значення для порожніх клітинок і стін.

Зображення має лише два зазначені вище канали. Напрямок робота надається один раз у полі верхнього рівня `direction`; він не дублюється всередині `image`.

## Дії

Для кодів `0`–`3` дії переміщення використовують таке абсолютне відображення:

| дія | значення |
|---:|---|
| 0 | рухатися вгору |
| 1 | рухатися вниз |
| 2 | рухатися ліворуч |
| 3 | рухатися праворуч |
| 4 | підібрати |
| 5 | покласти |


Поле `direction` вказує поточну орієнтацію за допомогою таких значень: 0 = угору (рядок - 1), 1 = униз (рядок + 1), 2 = ліворуч (стовпець - 1), 3 = праворуч (стовпець + 1).

Дія переміщення спочатку повертає робота в цьому абсолютному напрямку, а потім намагається перемістити його на одну клітинку. Стіна або предмет можуть заблокувати переміщення, але напрямок усе одно змінюється. `pick up` і `drop` діють виключно на суміжну цільову клітинку, визначену напрямком (наприклад, якщо direction=0, дія виконується над (row - 1, col)).

## Датасет

Ви отримуєте дві папки:

| Папка | Рядки | `labels.json`? | Використання |
|---|---:|---|---|
| `dataset/train/` | 60,000 | включено | навчання вашої моделі |
| `dataset/test_public/` | 3,600 | включено в копію для розробки | запуск і самостійне оцінювання вашого конвеєра |

Кожна папка містить `observations.json` — список JSON описаних
вище зразків. `labels.json` — це узгоджений список JSON дій (`0`–`5`).

Тренувальний набір містить рівно 10,000 рядків на кожного робота та 20,000 рядків із кожного
сімейства завдань. Відкритий тест містить 600 рядків на кожного робота. Обгорніть `image` у
`numpy.asarray(...)`, якщо вам потрібен масив.

Під час оцінювання `dataset/test_public/` непомітно замінюється прихованим набором із
3,600 спостережень у тому самому форматі, але без `labels.json`. Для відкритої
таблиці лідерів використовується `test_leaderboard_a`; для остаточного рейтингу використовується
`test_leaderboard_b`. Ноутбук, який безумовно зчитує мітки тестового набору, завершиться помилкою.
Зчитуйте мітки лише з `dataset/train/`.

## Виведення

Запишіть `predictions.json` у робочий каталог ноутбука. Це має бути список JSON,
що містить одну цілочисельну дію (`0`–`5`) для кожного рядка
`dataset/test_public/observations.json` у тому самому порядку. Для гіпотетичного тестового набору із шістьма зразками коректне виведення мало б такий вигляд:

```json
[0, 3, 2, 2, 5, 4]
```

Відсутній або некоректний файл JSON, неправильна кількість передбачень, нецілочисельне значення
або дія поза межами `{0,1,2,3,4,5}` відхиляються без оцінки.

## Оцінювання

Оцінка — це **середня точність за роботами** за шкалою `0`–`100`. Точність спочатку
обчислюється незалежно для кожного робота, а потім усереднюється за всіма шістьма роботами. Тому кожен
робот має однакову вагу.
