# Погоня роботов

- **Ограничение по времени:** 5 минут
- **Среда:** один GPU (≈16 GB VRAM), без доступа к интернету
- **Размер решения:** `solution.ipynb` ≤ 1 MB
- **Хранилище:** 5 GB 

## Задача

Имеется шесть роботов. Каждый робот действует в небольшой комнате, представленной в виде сетки. Каждая комната имеет игровую область `6×6`, окружённую стенами, поэтому полный массив `image` имеет размер `8×8` (игровая область + стены).

Каждый робот получает инструкцию на английском языке, описывающую задачу. Снимок может быть сделан в любой момент выполнения задачи роботом. Ваша цель — предсказать следующее действие робота.

Роботы не всегда следуют кратчайшему пути. Робот 0 может вести себя иначе, чем робот 1, но каждый робот следует собственному устойчивому шаблону поведения. Используйте обучающие примеры, включающие правильные следующие действия, чтобы изучить эти шаблоны.

![Робот](../robot.jpg)

Существует три типа задач:

- **дойти до** объекта, например `"approach the red ball"`;
- **поднять** объект, например `"grab the blue key"`;
- **положить один объект рядом с другим**, например
  `"place the red box beside the green ball"`.

Одна и та же инструкция может быть сформулирована несколькими способами. Тестовый набор может содержать новые **комбинации** знакомых фраз, цветов и типов объектов. Однако каждое слово, шаблон фразы, цвет, тип объекта и тип миссии, используемые в тестовом наборе, **также встречаются в обучающем наборе**.

Каждый пример содержит следующие поля:

| Поле | Значение |
|---|---|
| `robot_id` | к какому из 6 роботов относится пример (`0`–`5`) |
| `image` | комната — целочисленный массив `8×8×2`, в котором канал 0 содержит тип объекта object_idx (например, 1=пусто, 2=стена, 10=робот), а канал 1 содержит цвет объекта colour_idx (0–5). |
| `direction` | направление, в которое робот повёрнут лицом в данный момент |
| `mission` | инструкция на естественном языке |
| `carrying` | `null` или `[object_idx, colour_idx]` для переносимого объекта |

Строки представляют собой независимые снимки, расположенные в случайном порядке. Они не образуют эпизоды, и во время оценивания недоступны ни предыдущее наблюдение, ни предыдущее действие.

Предоставленный `visualize_dataset.ipynb` позволяет просмотреть наблюдения, доступные модели в различных ситуациях.

## Кодирование сетки

`image[row][column] = [object_idx, colour_idx]`. Первый индекс задаёт строку сверху вниз, а второй — столбец слева направо. Массив включает внешнюю границу из стен, поэтому доступная для перемещения внутренняя область имеет размер `6×6`.

Идентификаторы объектов:

| id | объект |
|---:|---|
| 1 | пустая клетка |
| 2 | стена |
| 5 | ключ |
| 6 | мяч |
| 7 | коробка |
| 10 | робот |
| 11 | токен |

Токены могут находиться в комнате, но никогда не упоминаются в миссиях.

Идентификаторы цветов: `0` — красный, `1` — зелёный, `2` — синий, `3` — фиолетовый, `4` — жёлтый и `5` — серый. Канал цвета не имеет значения для пустых клеток и стен.

Изображение содержит только два указанных выше канала. Направление робота задаётся один раз в поле `direction`; оно не дублируется внутри `image`.

## Действия

Для кодов `0`–`3` действия перемещения используют следующее соответствие:

| действие | значение |
|---:|---|
| 0 | переместиться вверх |
| 1 | переместиться вниз |
| 2 | переместиться влево |
| 3 | переместиться вправо |
| 4 | поднять |
| 5 | положить |


Поле `direction` указывает текущую ориентацию робота следующим образом: 0 = вверх (row - 1), 1 = вниз (row + 1), 2 = влево (column - 1), 3 = вправо (column + 1).

Действие перемещения сначала поворачивает робота в указанном направлении, а затем предпринимает попытку переместить его на одну клетку. Стена или объект могут заблокировать перемещение, но направление всё равно изменяется. `pick up` и `drop` действуют на **соседнюю** целевую клетку, определяемую направлением (например, если direction=0 (вверх) действие применяется к (row - 1, column)).

## Датасет

Вы получаете две папки:

| Папка | Строки | `labels.json`? | Назначение |
|---|---:|---|---|
| `dataset/train/` | 60,000 | включён | обучение модели |
| `dataset/test_public/` | 3,600 | включён в версию для разработки | запуск и самостоятельная оценка вашего пайплайна |

Каждая папка содержит `observations.json` — JSON-список описанных
выше примеров. `labels.json` — согласованный с ним JSON-список действий (`0`–`5`).

Обучающий набор содержит ровно 10,000 строк для каждого робота и 20,000 строк для каждого
типа задач. Публичный тестовый набор содержит 600 строк для каждого робота. Оберните `image` в
`numpy.asarray(...)`, если вам нужен массив.

Во время оценивания `dataset/test_public/` заменяется скрытым набором из
3,600 наблюдений в том же формате, но без `labels.json`. Для публичного лидерборда используется `test_leaderboard_a`; для приватного используется
`test_leaderboard_b`. Ноутбук, который пытается считать метки тестового набора, завершится с ошибкой.
Считывайте метки только из `dataset/train/`.

## Выходные данные

Запишите `predictions.json` в рабочую директорию ноутбука. Это должен быть список в формате JSON, содержащий одно целочисленное действие (`0`–`5`) для каждой строки
`dataset/test_public/observations.json` в том же порядке. Для гипотетического тестового набора, содержащего шесть примеров, корректный результат выглядел бы так:

```json
[0, 3, 2, 2, 5, 4]
```

Отсутствующий или некорректный JSON-файл, неверное количество предсказаний, нецелочисленное значение
или действие вне `{0,1,2,3,4,5}` отклоняются без начисления баллов.

## Оценивание

Метрика оценивания — **средняя точность по роботам** по шкале `0`–`100`. Сначала точность
вычисляется независимо для каждого робота, затем усредняется по всем шести роботам. Таким образом, каждый робот имеет одинаковый вес.

4. На вкладке Git в JupyterLab добавьте (через "+") и закоммитьте `solution.ipynb`, затем отправьте его в удалённый репозиторий.
5. Вернитесь на страницу соревнования и нажмите **Отправить**.

Отправьте ровно один файл с именем `solution.ipynb`.
