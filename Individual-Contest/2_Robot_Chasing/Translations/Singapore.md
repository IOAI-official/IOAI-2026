# 机器人追逐

- **时间限制：** 5 minutes
- **环境：** 1 GPU（≈16 GB VRAM），无互联网连接
- **解决方案大小：** `solution.ipynb` ≤ 1 MB
- **存储空间：** 5 GB 

## 任务

共有 6 个机器人。每个机器人都在一个由网格表示的小房间中行动。每个房间都有一个由墙壁包围的 `6×6` 可活动区域，因此完整的 `image` 数组大小为 `8×8`（可活动区域 + 墙壁）。

每个机器人都会收到一条描述任务的英语指令。快照可能是在机器人执行任务过程中的任意时刻拍摄的。你的目标是预测机器人的下一个动作。

机器人并不总是沿最短路径行动。机器人 0 的行为可能与机器人 1 不同，但每个机器人都遵循自身一致的模式。请使用包含正确下一步动作的训练样例来学习这些模式。

![机器人](../robot.jpg)

任务分为 3 种类型：

- **前往**某个物体，例如 `"approach the red ball"`；
- **拾取**某个物体，例如 `"grab the blue key"`；
- **将一个物体放到另一个物体旁边**，例如
  `"place the red box beside the green ball"`。

同一条指令可以有多种表述方式。测试集可能包含熟悉的短语、颜色和物体类型的新组合。但是，测试集中使用的每个单词、短语模式、颜色、物体类型和任务类型也都会出现在训练集中。

每个样本包含以下字段：

| 字段 | 含义 |
|---|---|
| `robot_id` | 这是 6 个机器人中的哪一个（`0`–`5`） |
| `image` | 房间，一个 `8×8×2` 整数数组，其中通道 0 存储类别型 object_idx（例如，1=空，2=墙，10=机器人），通道 1 存储类别型 colour_idx（0–5）。 |
| `direction` | 机器人当前朝向 |
| `mission` | 可见的自然语言指令 |
| `carrying` | 所携带物体对应的 `null` 或 `[object_idx, colour_idx]` |

各行是按随机顺序排列的相互独立的快照。它们不构成回合，并且评测时无法获得任何先前的观测或动作。

所提供的 `visualize_dataset.ipynb` 可用于查看模型在不同情形下能够获得的观测。

## 网格编码

`image[row][column] = [object_idx, colour_idx]`。第一个索引表示从上到下的行，第二个索引表示从左到右的列。该数组包含外围墙壁边界，因此可通行的内部区域为 `6×6`。

物体 id：

| id | 物体 |
|---:|---|
| 1 | 空单元格 |
| 2 | 墙 |
| 5 | 钥匙 |
| 6 | 球 |
| 7 | 箱子 |
| 10 | 机器人 |
| 11 | token |

房间中可能出现 token，但任务中从不提及它们。

颜色 id 分别为：`0` 红色、`1` 绿色、`2` 蓝色、`3` 紫色、`4` 黄色和 `5` 灰色。对于空单元格和墙壁，颜色通道没有意义。

图像仅包含上述 2 个通道。机器人的方向仅在顶层 `direction` 字段中提供一次；它不会在 `image` 内重复提供。

## 动作

对于代码 `0`–`3`，移动动作使用以下绝对方向映射：

| 动作 | 含义 |
|---:|---|
| 0 | 向上移动 |
| 1 | 向下移动 |
| 2 | 向左移动 |
| 3 | 向右移动 |
| 4 | 拾取 |
| 5 | 放下 |


`direction` 字段使用以下方式表示当前朝向：0 = 上（row - 1），1 = 下（row + 1），2 = 左（col - 1），3 = 右（col + 1）。

移动动作首先将机器人转向该绝对方向，然后尝试使其移动 1 个单元格。墙壁或物体可能会阻挡移动，但方向仍会改变。`pick up` 和 `drop` 仅作用于由方向确定的相邻目标单元格（例如，如果 direction=0，则作用于 (row - 1, col)）。

## 数据集

你会收到 2 个文件夹：

| 文件夹 | 行数 | `labels.json`？ | 用途 |
|---|---:|---|---|
| `dataset/train/` | 60,000 | 包含 | 训练模型 |
| `dataset/test_public/` | 3,600 | 开发版本中包含 | 运行流水线并自行评分 |

每个文件夹都包含 `observations.json`，它是由上述样本组成的 JSON 列表。`labels.json` 是一个与之对齐的动作 JSON 列表（`0`–`5`）。

训练集恰好包含每个机器人 10,000 行，以及每个任务类别 20,000 行。公开测试集包含每个机器人 600 行。如果需要数组，请使用
`numpy.asarray(...)` 包装 `image`。

评分时，`dataset/test_public/` 会被透明地替换为一个格式相同、包含
3,600 个观测但不含 `labels.json` 的隐藏集合。公开排行榜使用 `test_leaderboard_a`；最终排名使用
`test_leaderboard_b`。无条件读取测试标签的 notebook 将运行失败。
只能从 `dataset/train/` 读取标签。

## 输出

在 notebook 的工作目录中写入 `predictions.json`。它必须是一个 JSON
列表，按照相同顺序，为 `dataset/test_public/observations.json` 的每一行包含一个整数动作（`0`–`5`）。对于一个假设包含 6 个样本的测试集，有效输出可以是：

```json
[0, 3, 2, 2, 5, 4]
```

JSON 文件缺失或无效、预测数量错误、值不是整数，
或动作超出 `{0,1,2,3,4,5}`，都将被拒绝且不予评分。

## 评分

评分指标是在 `0`–`100` 范围内的**各机器人平均准确率**。首先分别计算每个机器人的准确率，然后对全部 6 个机器人的准确率取平均值。因此，每个机器人的权重相同。
